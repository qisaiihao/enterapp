### 核心思想：组件化拆分 (Componentization)

Vue/uni-app 的核心优势就是组件化。我们需要将这个巨大的页面分解成一个个独立的、功能单一的“积木”（组件）。每个组件只关心自己的模板(HTML)、逻辑(JS)和样式(CSS)，主页面则负责将这些“积木”拼装起来并协调它们。

**重构的好处：**
*   **代码清晰**：每个文件代码量急剧减少，逻辑一目了然。
*   **易于维护**：改一个功能，只需要去对应的小组件里修改，不会影响其他部分。
*   **便于复用**：像“作者信息”、“评论项”等组件，以后在其他页面也能用。
*   **提升性能**：组件化有助于更精细的渲染控制，避免不必要的全局刷新。
*   **方便协作**：不同开发者可以同时负责不同组件的开发，减少代码冲突。

### 重构路线图：一步步拆分你的页面

我们由外到内，从最独立、最明显的部分开始拆。建议你在 `pages/post-detail/` 目录下创建一个 `components` 文件夹，用来存放为这个页面拆分出去的组件。

#### 第 1 步：拆分独立的“功能弹窗”和“状态视图”

这些部分通常与主页面逻辑耦合度最低，最容易剥离。

1.  **加载骨架屏 (`PostDetailSkeleton.vue`)**
    *   **做什么**：将 `<block v-if="isLoading">...</block>` 里的所有骨架屏代码，剪切到一个新文件 `PostDetailSkeleton.vue` 中。
    *   **主页面**： `<post-detail-skeleton v-if="isLoading"></post-detail-skeleton>`

2.  **分享弹窗 (`ShareModal.vue`)**
    *   **做什么**：将 `<view v-if="showShareModal" class="share-modal-overlay">...</view>` 和隐藏的 `<canvas>` 相关的所有代码剪切到 `ShareModal.vue`。
    *   **Props**：接收 `show`, `post` 作为 props。
    *   **Data**：组件自己管理 `shareImageUrl`, `shareCanvasHeight` 等内部状态。
    *   **Methods**：`generateShareImage`, `drawCanvas`, `exportCanvas`, `saveShareImage` 等所有分享相关的逻辑全部搬过去。
    *   **Events**：当用户点击遮罩关闭时，通过 `$emit('hide')` 通知父组件。
    *   **主页面**： `<share-modal :show="showShareModal" :post="post" @hide="hideShareModal"></share-modal>`

3.  **编辑帖子弹窗 (`EditModal.vue`)**
    *   **做什么**：将 `<view v-if="showEditModal" class="edit-modal-mask">...</view>` 的代码剪切到 `EditModal.vue`。
    *   **Props**：接收 `show` 和 `post`。
    *   **Data**：组件自己管理 `editForm`。
    *   **Events**：点击取消时 `$emit('cancel')`，点击保存时 `$emit('save', this.editForm)`。
    *   **主页面**： `<edit-modal :show="showEditModal" :post="post" @cancel="onCancelEdit" @save="onSaveEdit"></edit-modal>`

#### 第 2 步：拆分核心内容区域

接下来，我们处理页面主体内容。

1.  **帖子头部信息 (`PostAuthorHeader.vue`)**
    *   **做什么**：将 `<view class="author-info">...</view>` 整块代码剪切过去。
    *   **Props**：接收 `post`, `isFollowing`, `isMutualFollow`, `showFollowButton` 等所有需要的数据。
    *   **Data**：组件自己管理 `followPending`。
    *   **Events**：当点击关注按钮时，`$emit('follow')`；点击用户头像时，`$emit('user-profile-tap', userId)`。
    *   **主页面**：在 `post-detail-wrapper` 内部，`<post-author-header :post="post" ... @follow="onFollowTap" @user-profile-tap="navigateToUserProfile"></post-author-header>`

2.  **帖子内容主体 (`PostDisplay.vue`)**
    *   **做什么**：将帖子标题、内容、图片、标签、发布时间等展示性内容 (`.post-title`, `.post-content`, `.image-container`, `.post-tags`, `.post-meta`) 剪切过去。
    *   **Props**：接收 `post`。
    *   **Data & Methods**：`swiperHeights`, `imageClampHeights` 和 `onImageLoad`, `handlePreview` 等图片处理逻辑也一起搬过去。
    *   **主页面**：`<post-display :post="post"></post-display>`

3.  **帖子操作栏 (`PostActions.vue`)**
    *   **做什么**：将 `<view class="vote-section">...</view>` 剪切过去。
    *   **Props**：接收 `post`, `isOwnPost`。
    *   **Events**：点击点赞 `$emit('vote')`，点击收藏 `$emit('favorite')`，点击编辑 `$emit('edit')`，点击分享 `$emit('share')`。
    *   **主页面**：`<post-actions :post="post" :is-own-post="isOwnPost" @vote="onVote" ...></post-actions>`

#### 第 3 步：拆分最复杂的评论区 (重点！)

评论区是重构的重中之重，可以分两层拆分。

1.  **评论列表 (`CommentList.vue`)**
    *   **做什么**：将 `<view class="comment-section">...</view>` 整个剪切到 `CommentList.vue`。
    *   **Props**：接收 `comments` 数组, `is-loading`。
    *   **主页面**：`<comment-list :comments="comments" :is-loading="isCommentLoading" @reply="showReplyInput" @delete="onDeleteComment" @like="toggleLikeComment"></comment-list>`

2.  **单个评论项 (`CommentItem.vue`)**
    *   **做什么**：在 `CommentList.vue` 内部，将 `v-for` 循环的 `<view class="comment-item">...</view>` 剪切到 `CommentItem.vue`。
    *   **Props**：接收单个 `item` (评论对象) 作为 prop。
    *   **Data**：组件自己管理 `showAllReplies` 状态。
    *   **Events**：所有操作（点赞、删除、回复、展开/收起回复）都通过 `$emit` 向上通知 `CommentList.vue`，再由 `CommentList.vue` 中转给主页面。
        *   例如：在 `CommentItem.vue` 里点击回复，触发 `$emit('reply', { commentId: item._id, authorName: ... })`。
    *   **`CommentList.vue` 的模板**：
        ```html
        <view class="comment-list">
            <comment-item 
                v-for="item in comments" 
                :key="item._id" 
                :item="item"
                @reply="$emit('reply', $event)"
                @delete="$emit('delete', $event)"
                @like="$emit('like', $event)"
            ></comment-item>
        </view>
        ```

#### 第 4 步：拆分底部评论输入框

这是最后一个大模块，它自身的状态和逻辑非常多。

1.  **评论输入组件 (`CommentInput.vue`)**
    *   **做什么**：将底部固定的两个输入框形态（`comment-input-area` 和 `bottom-action-bar`）以及遮罩层 `input-overlay` 全部逻辑剪切到新组件。
    *   **Props**：可以接收一个 `replyTo` 对象，包含 `commentId` 和 `authorName`。
    *   **Data**：`isInputExpanded`, `keyboardHeight`, `newComment`, `commentImages`, `isSubmitDisabled`, `isSubmittingComment` 等全部作为组件内部状态。
    *   **Methods**：所有与输入、选择图片、展开/收起、提交相关的函数 (`expandInput`, `collapseInput`, `onCommentInput`, `chooseImages`, `onSubmitComment` 等) 全部搬过去。
    *   **Events**：当用户提交评论时，`$emit('submit', { content: ..., images: ..., parentId: ... })`。
    *   **主页面**：`<comment-input @submit="onSubmitComment"></comment-input>`，并通过 `showReplyInput` 方法来命令式地调用组件内部方法或改变props来显示回复状态。

### 重构后的主页面 (`post-detail.vue`) 结构

经过以上步骤，你的 `post-detail.vue` 文件会变得非常清爽：

**`<template>` 会像这样：**

```html
<template>
    <view>
        <!-- 自定义返回按钮 -->
        <view class="custom-back-btn" @tap="goBack">...</view>
        
        <view class="container">
            <!-- 加载状态 -->
            <post-detail-skeleton v-if="isLoading"></post-detail-skeleton>

            <!-- 帖子加载失败 -->
            <error-state v-else-if="!post || !post._id"></error-state>

            <!-- 帖子内容 -->
            <block v-else>
                <view class="post-detail-wrapper">
                    <!-- 1. 作者信息 -->
                    <post-author-header 
                        :post="post" 
                        :is-own-post="isOwnPost"
                        ...
                        @follow="onFollowTap">
                    </post-author-header>

                    <!-- 2. 帖子展示 -->
                    <post-display :post="post" @tag-click="onTagClick"></post-display>

                    <!-- 3. 帖子操作 -->
                    <post-actions 
                        :post="post" 
                        :is-own-post="isOwnPost"
                        @vote="onVote"
                        @edit="onEditPost"
                        @share="onShare">
                    </post-actions>
                </view>

                <!-- 4. 评论列表 -->
                <comment-list 
                    :comments="comments" 
                    :is-loading="isCommentLoading"
                    @reply="handleReply"
                    @delete="onDeleteComment"
                    @like="toggleLikeComment">
                </comment-list>
            </block>
        </view>
        
        <!-- 5. 底部输入框 -->
        <comment-input ref="commentInput" @submit="onSubmitComment"></comment-input>

        <!-- 6. 各种弹窗 -->
        <share-modal :show="showShareModal" :post="post" @hide="hideShareModal"></share-modal>
        <edit-modal :show="showEditModal" :post="post" @cancel="onCancelEdit" @save="onSaveEdit"></edit-modal>
        <folder-selector ... ></folder-selector>
        <portfolio-selector ... ></portfolio-selector>

    </view>
</template>
```

**`<script>` 部分：**

*   **Data**: 只保留最核心的状态，如 `post`, `comments`, `isLoading`, `showShareModal` 等。
*   **Methods**: 主要剩下数据获取 (`loadPostDetail`, `getComments`) 和响应子组件事件的方法 (`onVote`, `onDeleteComment`, `onSubmitComment` 等)。页面本身变成了一个“指挥官”，负责数据的获取和分发，以及响应各种事件。

**`<style>` 部分：**

*   将每个组件对应的 CSS 剪切到各自的 `.vue` 文件中，并添加 `scoped` 属性，例如 `<style scoped>`。这可以防止样式全局污染。
*   主页面只保留一些全局布局相关的样式。

### 开始动手的小建议

1.  **做好备份**：在开始之前，一定用 Git 提交当前代码，或者复制一份文件做备份。
2.  **从简到繁**：先从 `PostDetailSkeleton.vue` 这种最简单的无逻辑组件开始，建立信心。
3.  **多用 Props 和 Events**：严格遵守“父组件通过 props 向子组件传递数据，子组件通过 events 向父组件发送消息”的原则。
4.  **善用 `v-bind`**：当一个组件需要传递多个 props 时，可以创建一个对象，然后使用 `v-bind="postObject"` 简化模板。

这个重构过程可能需要一些时间，但请相信，这是非常值得的投资。一旦完成，你的代码质量和后续的开发效率都会有质的飞跃。祝你重构顺利！

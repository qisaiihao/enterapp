# 活动链路码风建议（可复用）

## 1. 分层边界
- 页面层：只做状态管理、交互反馈、路由跳转，不直接 `cloudCall('adminManager')`。
- `api-cache` 层：负责云函数调用、结果解包、缓存策略与失效策略。
- 云函数层：负责参数归一化、鉴权、数据库读写、错误日志。
- 公共工具层：沉淀活动通用逻辑（日期、状态、参数解码），页面不重复实现。

## 2. 命名与常量
- 状态常量只维护一份：`ACTIVITY_STATUS_OPTIONS`，所有页面复用。
- 缓存 key 命名格式固定：`page:{page}:size:{size}:...`，禁止页面自造格式。
- 本地刷新标记统一前缀：`shouldRefresh*`，一个页面只消费自己约定的 key。
- 管理端接口函数命名统一：`list/get/create/update/setStatus/delete + AdminActivity`。

## 3. 错误处理与日志
- `api-cache` 层统一解包 `res.result`，失败统一抛 `Error(message)`。
- 页面层只处理 toast 与兜底文案，不做协议解析。
- 云函数日志统一前缀：`[fnName]`，错误日志必须包含原始 error。
- 业务校验失败返回 `{ success: false, error: '...' }`，保持前端可直接展示。

## 4. 功能不变重构清单
- 不修改云函数 action 名、入参字段、返回字段。
- 不修改路由 query 字段名（如 `activityId/title/summary/...`）。
- 不修改缓存 namespace 与已有失效入口方法名。
- 不修改下拉刷新、触底分页、乐观点赞/失败回滚行为。
- 不引入新的默认业务规则（只抽取和复用已有逻辑）。

## 5. 提交前自检
- 管理端：列表/创建/编辑/状态切换/删除功能与原行为一致。
- 用户端：活动列表与详情分页、状态展示、点赞与跳转一致。
- 参加活动选择：`preview` 的活动日期展示与选择回填一致。
- 关键文件可通过基础语法检查（`node --check`）且无引用丢失。

## 缓存与刷新约定

- `cache/core/manager.js`：同命名空间、同键的并发加载共用请求，包括缓存未命中和 SWR 后台更新。每个 SWR 消费者仍能收到自己的更新回调。失败后释放请求，下一次读取可重试。
- `set`、有效 `update`、`delete`、`clear` 会取消旧请求写回与后台通知的资格；不取消已发出的网络请求。原有等待者仍会收到其原请求结果，页面自身的账号/请求版本校验仍须保留。
- 未读数：前台轮询从 30 秒调整为 120 秒，后台停止。顶部栏普通刷新与短时间返回前台复用最近两分钟的成功结果；手动强刷立即查询；消息页进入时原有刷新逻辑保留。已读操作继续通过事件立即更新红点。账号切换重置刷新时间并拒绝旧账号响应。
- 广场气泡：公共配置持久缓存 5 分钟；保存成功立即覆盖本机缓存。其他设备最长等缓存到期后下一次进入广场读取新配置。
- 活动红点：普通进入/返回广场不再强制清缓存，沿用活动 API 的 60 秒 TTL 和 30 秒 SWR。
- 我的帖子：按账号、页码、每页数量、原创筛选隔离，缓存 60 秒，不使用 SWR。手动刷新直接失效；发布、编辑和可见性事件清缓存；个人页删除接口已有的失效逻辑保留。点赞和评论数仍走现有缓存同步。

## 收益口径

持续前台运行时，未读数定时查询由约 120 次/小时降至 30 次/小时（不含进入消息页和手动刷新）。三个同时读取同键的消费者由三次加载降至一次。整体套餐调用量还受业务请求、存储和身份认证等影响，不能据此承诺总调用量降幅。发布后应按相近活跃人数与使用时长对比控制台调用明细。

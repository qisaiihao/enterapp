# 帖子图片链接统一解析

日期：2026-09-29。最低兼容客户端：1.7.0。本地实施完成；未部署云端或发布客户端。

## 协议与实现

新版 `cloudCall` 为五个列表接口附带 `rawImages: true`：`getPostList`、`getHotFeed`、`getFollowingPosts`、`getDiscussionPosts`、`getRecommendationFeed`。服务端在该参数严格为布尔 true 时跳过临时链接转换；客户端返回给页面前统一调用现有 `hydrateTempUrls` 和 `fileUrlCache`。

1.7.0 不带能力参数，仍走原 HTTPS 转换路径。新版遇到尚未部署的服务端也能继续处理 HTTPS。显式发送 `rawImages: false` 可回退。推荐接口逐级传递该参数，未使用云函数进程全局状态，避免并发请求相互影响。

帖子图片、原图、头像、签名及背景图复用同一文件链接缓存。原有按文件合并在途任务、每批最多 50 个、部分失败重试及过期安全裕量继续生效。帖子保留 `_cloudFileSources` 元数据，以便显示地址被替换、对象复制或缓存持久化后仍能重新解析原文件 ID；页面主动换图时以新字段为准，旧元数据不能把新图覆盖。

本项不涉及字体接口、字体资源或 App 字体注册。没有改变存储权限、上传路径及帖子分类规则。

## 收益与验证

新增 `scripts/test-post-image-links.cjs` 验证五个真实函数入口的新旧协议；聚合复杂的接口使用固定聚合结果测试媒体处理，排序/查询语义由原帖子回归覆盖。客户端运行实际链接缓存与 `cloudCall`，验证并发响应共享一次换链、有效链接复用、持久化后续期和换图保护。

确定场景：同一文件同时出现在两个接口响应里时，服务端新协议不换链，客户端只做一次批量解析；之后在有效期内复用链接。不能据此推算整体套餐费用降幅；首次读取可能增加一次客户端链接请求，需要真机观察总延迟。

## 发布

先部署上述五个云函数（保留各自 `_lib` 依赖及现有运行时配置），再发布客户端；顺序颠倒也有 HTTPS 回退。上线后分别检查 1.7.0 默认请求和新版请求，验证图片、原图预览、头像、签名、背景及部分换链失败的重试。

本轮未连接生产部署。自动测试不能证明云端文件权限、真实弱网及 App/小程序图片实际显示；这些仍需上线及真机验收。

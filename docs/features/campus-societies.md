# 高校诗社

更新：2026-11-02。后续补充：成员与通知管理。

## 当前能力

沿用 `pages-community` 的页面体系（现为 13 个页面）、`api-cache/societies.js` 和腾讯云 `societyManager`，没有另建一套账号或诗歌数据库。

| 流程 | 实现 |
| --- | --- |
| 入驻 | 申请、材料上传、平台审核、通过后事务创建诗社与负责人 |
| 成员 | 关注、申请加入、撤回、管理员通过/拒绝、成员展示；入社通过后自动关注诗社，入驻创建的负责人也自动关注，之后可自行取消关注；成员目录独立页面，负责人和管理员置顶；诗社可设置公开招募或仅限本校 |
| 动态 | 管理员发布、编辑、置顶/取消置顶、删除 |
| 活动 | 发布/编辑/下架、参与范围、截止时间、人数上限、报名/取消、分页预约名单 |
| 联合征稿 | 发布/编辑/下架、邀请合办诗社、合办方管理员确认、收稿范围、截止时间 |
| 投稿 | 从本人公开且审核通过的原创诗歌中选择、提交、撤回、退回后重新投稿、分页我的投稿 |
| 评审 | 待审及旧待定稿件依次评审；通过/退回写入结果，待定仅跳过当前稿件；版本冲突检查、审核记录、征稿详情展示已入选稿件 |
| 作品 | 成员关联发表、入选稿件自动关联主办诗社、社内及作者作品查询 |
| 管理统计 | 成员、作品、报名人数、稿件数、本周新增、进行中活动数 |
| 成员管理 | 成员退出、负责人移除成员及任免管理员、移交负责人；公开与管理成员列表分页 |
| 诗社资料 | 管理员修改名称、地区、口号、简介和头像；名称仍按学校内唯一约束，文本和头像先审核 |
| 诗社通知 | 独立页面和入口，按入驻、成员、活动、投稿、合办分类；私有收件箱和未读状态 |

作品继续使用同一条 `posts` 记录。`society_publications` 只保存关联，不复制正文、点赞、评论。征稿详情可选已写的诗，选诗行复用作品集选诗组件；也可跳转现有创作页，成功发表原创诗歌后自动提交至本次征稿。若诗歌已发表而投稿失败，保存作品 ID，返回征稿页重试投稿，不重复发表诗歌。非公开、隐藏、匿名、删除、待审核作品不能投稿或关联发表；非原创诗歌不能投稿征稿（成员关联发表不受此限制），服务端与选诗列表都会校验原创状态。

联合征稿由主办方邀请；被邀请诗社的管理员确认后，该诗社才出现在公开合办名单，并取得本次征稿的评审权限。主办方可以修改征稿、移除合办；合办方不能编辑主办方的征稿。收稿范围可选“公开征稿”（所有用户）、“仅限本校”（主办或已确认合办诗社的同校学生）、“限本诗社”（主办或已确认合办诗社的成员）；发布、编辑、征稿卡片和详情页使用相同文案。旧征稿未设置范围时按公开征稿显示。入选作品关联主办诗社，其他诗社不会被自动写入作品。

本周统计以 Asia/Shanghai 周一零点为边界。征稿卡片的收稿数统计未撤回稿件（含已退回）；退回重投不会重复增加，撤回后重投恢复计数。

## 页面与设计

- 首页“推荐诗社”按当前用户个人资料优先推荐同校诗社，其次推荐同地区诗社；学校和地区支持包含式模糊匹配（如“广州市”匹配“广州”），资料未填写或匹配不足时随机补齐，最多展示 3 个。
- 首页、诗社主页和管理页不额外显示“高校诗社”“诗社主页”“诗社管理”等导航标题；已有设计中的标题保留。
- 首页“联合征稿”的标题和“更多”进入独立列表页；列表页沿用正在进行/即将截止/往期三种筛选，滑动到底部自动加载下一页。首页每屏最多显示 6 条，“更多”随当前筛选的数量显示（即将截止每屏 3 条）。列表页右上角提供筛选按钮，可切换“查看全部”/“仅看可参与”；“可参与”按征稿的收稿范围判断，仅限本校的征稿只对学校匹配的用户可见，限本诗社的征稿只对主办或已确认合办诗社成员可见。征稿卡片的“征稿中/已截止”状态旁及详情页显示对应收稿范围，学校匹配沿用包含式模糊匹配。
- 诗社主页统计栏的“成员”进入独立成员目录页；目录分“负责人与管理员”和“全部成员”两段，负责人、管理员固定在前，成员按加入时间分页加载，点击成员进入其诗社个人主页。
- 诗社资料包含“招募范围”（`recruitment`：`open` 公开招募 / `school` 仅限本校），入驻申请、管理页资料编辑均可设置，诗社详情页在“学校 · 地区”下方展示；仅限本校在入社申请和审核通过时均按用户学校校验，旧数据缺省按公开招募处理。首页和发现页按服务端返回的关注状态显示。
- 活动管理复用 `OpportunityCard`；首页“最新诗社作品”使用与周刊详情页共用的 `PoemStack` 左右滑动叠卡，`SocietyStackFront` 固定卡片右上角的头像尺寸并显示签名图，卡片下方不显示作者、日期和页码。首页作品默认取当前用户已加入诗社的作品；未加入任何诗社或未登录时展示全部诗社作品。诗社主页“作品”标签和诗社个人主页共用广场 `PostItem` 信息流，支持继续加载后续作品；作者头像、标题、正文预览及评论点赞区与广场一致。列表、标签、错误重试沿用已有组件。
- 活动/征稿详情页的主办方显示为“主办诗社”；只有存在已确认的合办诗社时才额外显示“合办诗社”，未填写合办诗社时不显示该分组。
- `SocietyEditor` 承接设计未提供的发布/编辑表单，只提供字段和操作；复用上传及内容审核服务。
- `WorkPicker` 在报名/投稿详情及诗社作品页内使用，不新增路由。
- `SubmissionReview` 像作品详情页一样平铺显示当前诗歌的完整正文；组诗逐节显示，保留原文换行和缩进。页面只保留通过、待定、退回操作，处理后自动进入下一首。待定只在本轮跳过，不写入评审结果；重新进入时仍可看到该稿件，以及此前已保存为待定状态的稿件。
- 字体加载路径、注册时机、绘制名称、字体资源均未改动。

## 接口

所有业务调用均经 `societyManager`，保留原有入驻、关注、成员、公开读取接口，新增：

| action | 用途 |
| --- | --- |
| saveContent / editContent / changeContent | 动态、活动、征稿的发布、编辑、置顶、下架/删除 |
| callList | 公开征稿列表，按正在进行/即将截止/往期筛选并分页；`availableOnly` 仅返回当前用户可参与的征稿；首页“更多”使用同一入口 |
| manageContent | 当前诗社管理内容分页；包括合办征稿与待确认邀请 |
| acceptHost | 被邀请诗社的管理员确认合办 |
| registration / registrations | 报名/取消、管理员分页名单 |
| myWorks / publishWork | 本人可选诗歌、成员关联发表 |
| submitWork / withdrawWork | 投稿、撤回 |
| submissions / reviewWork | 管理员分页稿件、评审 |
| myParticipation | 当前账号的投稿或报名记录分页 |
| statistics | 管理统计 |
| memberDirectory | 公开成员目录：负责人、管理员置顶，成员分页 |
| clearNotifications | 当前账号确认后清空全部分类的诗社通知，其他账号通知不受影响 |

`opportunity` 在征稿类型下额外返回该征稿的已入选作品 `works`（仅包含仍公开可展示的原作）；征稿详情页复用广场 `PostItem` 信息流展示，不复制正文或另建作品数据。

发布请求使用稳定 requestId；编辑和评审使用 revision。报名、投稿、评审及作品关联计数均在事务内更新，支持并发冲突重试；事务按“先读后写”执行。最后一个报名名额不会被重复占用。

稿件保存原作内容摘要。评审通过时重新读取原作并校验作者、可公开状态及内容摘要；原作修改后须退回重投。客户端不能提交任意作者或管理员身份。

动态/活动/征稿文本、封面、嘉宾资料复用 `contentCheck` 和共享 `moderation-gate`；审核失败或不可用时不写入公开内容。函数超时配置为 300 秒，发布调用配置相应等待时间。

## 数据、身份和权限

原有 13 个集合保留：`societies`、`society_applications`、`society_names`、`society_members`、`society_join_requests`、`society_follows`、`society_publications`、`society_news`、`society_events`、`society_calls`、`society_audit_logs`、`society_sessions`、`society_auth_attempts`。其中 `society_sessions`、`society_auth_attempts` 是旧版二次密码校验的遗留集合，当前代码不再读写。

新增：

- `society_registrations`：按活动+用户确定唯一文档，保存报名/取消状态。
- `society_submissions`：按征稿+用户+原作确定唯一文档，保存状态、版本、原作摘要及评审信息。
- `society_notifications`：按接收人隔离的诗社通知，记录分类、跳转目标和已读状态。入驻及入社审核、成员职务变化、活动报名、投稿评审、合办邀请及确认写入通知。

全部 16 个集合为 `ADMINONLY`，不允许客户端直接读写。查询索引清单在 `scripts/deploy-societies.cjs`，部署时按字段检查已有索引，只新增缺失索引，不删除索引或业务数据。

- 小程序由可信微信云上下文及已有绑定映射确定账号。
- App/H5 直接使用 App 登录账号：客户端 `cloudCall` 注入当前登录账号，小程序优先使用可信微信上下文及绑定映射。可信微信身份匹配到账号时仍以其为准并拒绝其他账号声明；App/H5 的 TCB 运行时 uid 不是微信身份，匹配不到账号时回退到客户端注入的登录账号。未登录返回 `AUTH_REQUIRED`，客户端提示去登录；已登录即可正常使用，不再要求输入密码二次确认，也不再签发诗社会话。
- 个人资料、报名名单、投稿记录不进入共享持久化列表缓存。请求完成及图片临时链接处理结束后都检查账号是否变化。
- 管理权限从当前诗社成员记录读取；平台入驻审核仍读取 `adminConfig/admin.adminPoemIds`。
- 报名名单仅投影昵称、头像、用户标识和报名时间，不返回电话、密码或登录凭据。
- 证明材料仍须使用私有云存储规则；本次部署没有修改存储桶权限，也未做双账号证明材料访问验收。

## 部署

既有服务已由用户部署；本次查询确认 `societyManager` 和原有 13 个集合存在。旧版文档的“未部署”不再代表当前状态。

```powershell
# 只预览，不访问云端
node scripts/deploy-societies.cjs

# 备份现有函数、补集合与权限/索引、只更新 societyManager、只读线上验收
node scripts/deploy-societies.cjs --apply

# 仅检查运行状态、公开读取和未登录鉴权
node scripts/deploy-societies.cjs --verify

# 单独维护集合，预览默认不访问云端
npm run init:societies-db
npm run init:societies-db -- --apply
```

目标环境来自 `cloudbaserc.json`：`cloud1-5gb0pbyl400845f5`。复用 CloudBase CLI 登录态，不把密钥写入项目。只部署诗社函数；不改动已有短信/登录函数。备份及线上检查结果位于 `output/societies-deploy-20261102/`。没有写入线上演示诗社、用户、活动或稿件。

此前云端已更新 `societyManager`，新增 `society_notifications` 并验证 16 个集合的管理端权限和通知索引；线上公开读取及 19 项接口鉴权检查通过。本次本地修补尚未部署，App/小程序客户端也需使用新构建，不能靠更新云函数自动更新旧客户端。

# 微信绑定与登录梳理

日期：2026-09-30。最低支持客户端为 1.7.0。本地实现与自动测试完成，生产云函数、数据库规则及客户端尚未发布，真机验收未进行。

## 账号与微信的关系

账号 `_openid` 是历史内容的归属标识，绑定和换绑都不修改它，也不迁移作品、收藏、作品集。`wechatOpenId` 表示当前微信登录入口。微信身份只来自云函数 `cloud.getWXContext().OPENID`；请求里传入的 `openid`、旧账号 ID 或公开 Poem ID 都不能代替登录验证。

新增两个仅服务端可读写的集合：

| 集合 | 文档键 | 用途 |
| --- | --- | --- |
| `wechat_bindings` | 微信 OPENID 的 SHA-256 | 当前微信对应的用户文档 ID；空 `userId` 标记已解除的旧映射 |
| `wechat_binding_grants` | 微信 OPENID 与用户文档 ID 组合的 SHA-256 | 密码或短信校验成功后签发的五分钟绑定凭据 |

绑定凭据不下发客户端。它绑定当前微信、目标用户和账号凭据指纹；过期、已经消费或密码/手机号/Poem ID 等发生变化后不可继续绑定。确认换绑与消费凭据在同一事务提交。直接传 `forceRebind: true` 不会绕过验证；同一账号已经完成绑定时返回幂等成功。

共享实现位于 `functions/_shared/wechat-auth/index.js`，由 `npm run sync:wechat-auth` 同步到四个独立部署目录的 `_lib/wechat-auth.js`，质量门禁检查副本一致。不能只上传 `_shared` 目录而漏掉函数自己的 `_lib`。

## 各种登录与冲突

| 场景 | 行为 |
| --- | --- |
| App / H5 账号登录，没有微信 OPENID | 按原账号登录，不创建微信绑定凭据 |
| 当前微信已经是该账号的原生或显式绑定入口 | 不重复提示绑定 |
| 密码或短信登录另一个账号 | 暂存登录结果，询问是否绑定；跳过仍可登录该账号 |
| 当前微信已有原生注册账号 | 返回兼容的 `OPENID_CONFLICT`，确认后解除原账号的此微信入口 |
| 当前微信显式绑定了另一账号 | 返回 `WECHAT_ALREADY_BOUND`，确认后换绑 |
| 目标账号已绑定另一微信 | 返回 `WECHAT_ALREADY_BOUND`，新版区分提示目标账号的旧微信也会解除 |
| 微信端与目标账号两侧同时冲突 | 同时提示受影响的关系，确认后在一个事务里更新 |
| 绑定凭据超时或账号信息已变化 | 清理待绑定状态，要求重新密码/短信登录 |
| 旧数据库存在重复微信关联 | 返回 `AMBIGUOUS_WECHAT`，不任意挑一个账号或自动合并 |
| 新微信并发首次登录 | 用确定用户文档键和事务避免重复注册 |

事务只使用文档读写，并在写入前完成读取，符合 [CloudBase 事务约束](https://docs.cloudbase.net/database/transaction)。微信登录和换绑操作同一映射文档，使并发争用触发事务重试；这保证服务端提交时的关系一致，不代表已经登录的客户端会被自动远程注销。

历史用户无须提前批量迁移：首次登录读取现有 `wechatOpenId` / `_openid` 关系并建立映射。原生账号失去微信入口后标记 `wechatLoginDisabled`，避免 `_openid` 回退误登录。旧微信已解除后不能继续进入被换绑的账号；如果它从未注册过自己的原生账号，随后微信登录可能创建一个新账号，现有原生账号则返回重新使用账号方式登录的提示。

用户数据不会被删除，但只有微信入口的原账号可能失去自助访问方式，因此确认界面提示先完善密码等登录方式。已有手机号/GitHub 等登录入口不由本次换绑修改。

## 客户端整理

`mixins/wechatBinding.js` 统一三条提交路径：首次绑定、确认重新绑定、确认原生账号冲突。保留跳过、取消返回上一级和失败重试；提交中阻止重复请求。页面退出或待登录对象被替换后，旧响应不能落入新会话，退出后清理延迟跳转。

账号切换成功时调用现有缓存重置入口，同账号刷新不清缓存。成功后清理密码与登录短信输入。微信云调用已经携带可信微信上下文，移除原来只获取而未使用的 `wx.login` code。登录响应不返回密码、密码哈希、盐及重置/访问/刷新令牌字段，也不再打印整个密码登录响应。

## 1.7.0 兼容与停用范围

保留 `loginWithCredentials`、`loginWithPhone`、`loginWithWechat`、`bindWechatToAccount` 函数名、主要返回字段、原来的两种冲突代码，以及 `{ poemId, forceRebind }` 绑定参数。1.7.0 无需携带新令牌，重新密码/短信登录即可取得服务端凭据；部署前已经打开的旧绑定弹窗可能需要重新登录。旧版冲突文案较笼统，新版才区分微信侧与账号侧冲突。保留 App / H5 和既有 Poem ID 登录格式。

旧 `bindWechatOpenid` 接受客户端旧 ID 并批量改写内容归属，现已返回 `LEGACY_BINDING_DISABLED`，不读写业务数据。现有业务源码没有该调用；本地 `unpackage/app-update-release/poementer-1.7.0.apk` 的 `app-service.js` 也只包含 `bindWechatToAccount`，未包含该旧入口。APK 静态检查不能替代 1.7.0 微信小程序真机验收。作品集回归仍检查全部 1001 条记录、文件夹 ID 与可见性保持原样，并能按原归属完整读取。

## 部署顺序

1. 在目标环境创建 `wechat_bindings`、`wechat_binding_grants`，客户端权限均设置为禁止读写（例如自定义规则 `{"read":false,"write":false}`），服务端云函数使用管理员权限。不得设置客户端可写，否则绑定凭据可以被伪造。文档键支持直接查询；现有 `users.poemId`、`users._openid`、`users.wechatOpenId` 查询继续使用现有数据库索引策略。
2. 本地执行 `npm run sync:wechat-auth`、`npm run test:login`。部署 `loginWithCredentials`、`loginWithPhone`，连同各自 `_lib`，让 1.7.0 和新版的已验证登录都能建立凭据。缺少集合或服务端权限会导致需绑定的登录失败，先在测试环境确认。
3. 在同一发布窗口部署 `bindWechatToAccount`、`loginWithWechat` 及其 `_lib`，再部署停用版 `bindWechatOpenid`。不要长时间混用新登录映射和旧换绑写入逻辑；旧换绑不维护新映射。
4. 用测试账号完成下面的验收，再发布小程序及其他客户端。已经注册的用户按需建立映射，无须全量数据脚本。没有执行线上清理或历史账号合并。

如需回退，不能只回退某一个绑定函数并让两套写入规则混用；先暂停换绑入口，再统一处理函数版本和映射状态。Git 存档用于恢复代码，不自动回退数据库。凭据每个“微信 + 账号”组合复用一条记录，过期校验不依赖定时清理；本轮未增加 TTL 清理任务。微信登录增加映射读写、换绑增加事务操作，这是为一致性付出的成本，本项不声称降低登录数据库费用。

## 自动测试及真机验收

`npm run test:wechat-auth` 覆盖真实函数入口与共享模块：可信身份、无密码强制绑定拒绝、凭据过期/消费/账号变化、1.7.0 请求、原生/显式/双侧冲突、事务失败回滚、并发注册、同微信换绑多个账号、多微信争抢一个账号、旧入口回退阻断、重复关系拒绝与敏感字段过滤。运行真实 mixin 和页面方法，检查取消、跳过、重复点击、失败重试、旧响应丢弃、缓存重置与退出后不跳转。短信回归另检查验证成功签发凭据及验证码不可重放。

自动事务测试采用内存快照和冲突重试模拟，不等于真实云数据库压测。完整 `check:quality` 通过；最终各端构建结果见交付文档。

待真机验证：

- 1.7.0 与新版分别测试密码、短信和微信登录，已绑定账号不重复弹窗。
- 仅微信注册的原账号、已有密码/手机的原账号、另一微信已绑定的目标账号；检查文案、取消和确认后的登录结果。
- 换绑前后打开同一账号的收藏、作品、私有作品集，原账号通过原密码/手机号仍可读取自己的内容。
- 弱网、五分钟超时、退出页面和连续点击，确保无重复提交及错误跳转。
- 两部手机并发注册/换绑，核对云端映射与用户字段；真实数据库规则阻止客户端访问凭据集合。

## 本次边界

没有迁移现有密码存储格式，没有统一改造所有业务接口的身份验证，也没有实现全局会话撤销。例如现有部分接口依赖客户端传入账号标识、部分账号资料写入口的字段权限，仍需要独立的服务端鉴权梳理。这里完成的是微信绑定验证与关系一致性，不能视为整个账号系统已经完成安全改造。字体路径、加载时机和绘制名称均未修改。

# 微信绑定功能逻辑检查清单

## 修复的问题

### 问题 1：loginWithCredentials 自动更新 openid
**原问题**：云函数在检测到 openid 不同时，会自动更新数据库，导致前端无法询问用户。

**修复方案**：
- 云函数不再自动更新 openid
- 返回 `needBindWechat` 标志和 `currentOpenid`
- 前端根据标志显示绑定弹窗

### 问题 2：loginWithPhone 也有同样问题
**修复方案**：同样修改为不自动更新，返回标志

### 问题 3：getWxContext 方法不必要
**修复方案**：删除该方法，直接使用云函数返回的 `currentOpenid`

## 完整流程验证

### 场景 1：用户 A 在微信 A 中用 Poem ID 登录（openid 相同）

1. ✅ 用户输入 Poem ID 和密码
2. ✅ 调用 `loginWithCredentials` 云函数
3. ✅ 云函数检测：`currentOpenid === userInfo._openid`
4. ✅ 返回：`needBindWechat: false`
5. ✅ 前端直接完成登录，跳转主页
6. ✅ 不显示绑定弹窗

**预期结果**：正常登录，无弹窗

### 场景 2：用户 A 在微信 B 中用 Poem ID 登录（openid 不同）

1. ✅ 用户输入 Poem ID 和密码
2. ✅ 调用 `loginWithCredentials` 云函数
3. ✅ 云函数检测：`currentOpenid !== userInfo._openid`
4. ✅ 返回：
   - `needBindWechat: true`
   - `openid: userInfo._openid`（旧的）
   - `currentOpenid: wxContext.OPENID`（新的）
5. ✅ 前端检测到 `needBindWechat: true`
6. ✅ 显示绑定微信弹窗
7. ✅ 用户选择：
   - **确认绑定**：调用 `bindWechatOpenid` 云函数
   - **跳过**：使用旧 openid 登录

**预期结果**：显示弹窗，用户可选择

### 场景 3：用户确认绑定微信

1. ✅ 用户点击"确认绑定"
2. ✅ 调用 `bindWechatOpenid` 云函数
3. ✅ 云函数验证身份：`poemId + oldOpenid`
4. ✅ 批量更新 10 个集合的 openid
5. ✅ 返回更新统计
6. ✅ 前端更新全局数据和缓存（使用新 openid）
7. ✅ 显示成功提示："绑定成功！已更新 X 条数据"
8. ✅ 跳转主页

**预期结果**：数据全部更新，使用新 openid

### 场景 4：用户跳过绑定

1. ✅ 用户点击"跳过"
2. ✅ 使用旧 openid 完成登录
3. ✅ 更新全局数据和缓存（使用旧 openid）
4. ✅ 跳转主页

**预期结果**：使用旧 openid，数据不变

### 场景 5：微信授权登录（不受影响）

1. ✅ 用户点击"微信授权登录"
2. ✅ 调用 `loginWithWechat` 云函数
3. ✅ 使用当前微信的 openid 查询或创建用户
4. ✅ 直接完成登录
5. ✅ 不显示绑定弹窗

**预期结果**：正常登录，无弹窗

## 边界情况检查

### 边界 1：oldOpenid === newOpenid
✅ 云函数检测到相同，返回成功但不更新
```javascript
if (oldOpenid === newOpenid) {
  return { success: true, message: 'openid 相同，无需更新' };
}
```

### 边界 2：用户身份验证失败
✅ 云函数验证 `poemId + oldOpenid` 不匹配
```javascript
if (userRes.data.length === 0) {
  return { success: false, message: '用户验证失败' };
}
```

### 边界 3：云函数超时
✅ 设置超时时间 60 秒
✅ 使用分页查询，每次最多 1000 条
✅ 如果数据量特别大，可能需要多次调用

### 边界 4：部分更新失败
⚠️ 当前实现：如果某个集合更新失败，会抛出异常
🔧 建议改进：使用 try-catch 包裹每个集合的更新，记录失败的集合

### 边界 5：用户在绑定过程中关闭小程序
✅ 云函数会继续执行完成
✅ 下次登录时，如果已部分更新，可能出现数据不一致
⚠️ 建议：添加事务支持或回滚机制

## 已知限制

1. **不可逆**：绑定后无法恢复旧 openid
2. **无事务**：更新过程中如果失败，可能导致数据不一致
3. **性能限制**：数据量过大可能超时
4. **仅小程序**：H5 和 App 不支持此功能

## 改进建议

1. **添加事务支持**：确保数据一致性
2. **添加回滚机制**：更新失败时回滚
3. **添加进度提示**：显示更新进度
4. **添加日志记录**：记录绑定操作
5. **添加绑定历史**：记录 openid 变更历史
6. **优化性能**：使用批量更新 API

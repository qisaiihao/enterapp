# 诗歌卡片行首空格

2026-10-28：修复原创页诗歌卡片丢失行首空格、与详情页显示不一致的问题。

## 原因与展示规则

原创页通过 `utils/poemDisplay.js` 生成展示字段，旧逻辑删除了每个内容行的行首空白；详情页直接显示原文。卡片本身已使用 `white-space: pre-wrap`，无需调整样式或字体。

展示处理现在保留内容行的缩进，包括普通空格、全角空格、Tab 和其他 Unicode 空格，行中、行尾空格也保持原样。正文、高光句、组诗使用相同规则。仍将纯空白行规范为空串，移除正文开头的空白行，保留诗节之间的空行；CRLF 换行统一为 LF。高光列表仍过滤纯空白项。

该规则也适用于复用工具的山页面、活动、周榜、作品集和发布预览。活动卡片的限行预览只筛除空白行，不再裁掉内容行的缩进。原始 `content`、`highlightLines`、`seriesBlocks` 不变，无需修改云端数据或部署云函数。

## 回归检查

- `npm run test:poem-display`：正文、高光、组诗、空行、CRLF、原文不变、原创页展示字段重新计算以及限行预览。
- `npm run test:activity-cards`：活动与原创页卡片交互及同步。旧的“删除全角空格”断言改为精确验证保留缩进。
- `npm run check:quality`、`npm run build:app`。

自动检查不等于真机验收。真机复核需发布带普通空格、全角空格和多行缩进的诗歌，比较原创页折叠、高光、展开、组诗翻页与详情页的显示。本次未改变字体路径、注册时机或 Canvas 绘制名称。

本次验证：新增回归在修复前复现失败，修复后通过；`npm run check:quality` 和 `npm run build:app` 均通过，尚未真机验收。

## 组诗缓存与完整翻页（2026-11-11）

原创页的 `seriesPoems` 是派生展示字段。旧缓存可能只有前三首，不能覆盖 `seriesBlocks` 中完整的七首。`attachPoemDisplayFields()` 现在优先从原始 `seriesBlocks` 重新生成展示数据；仅在原始分块缺失或为空时兼容旧的 `seriesPoems`。

如果列表声明的 `seriesBlockCount` 大于实际可读分块数，点击卡片会通过现有详情 API 强制获取完整分块，再展开逐首阅读。完整列表不增加详情请求，补齐后再次展开也直接复用。补齐失败保持封面并允许重试，不把三首显示成完整组诗。连续点击不会重复请求；补齐时保留点赞状态、允许加载下一页，刷新后的卡片不接受旧结果。

回归覆盖 `npm run test:poem-display` 中的七首翻页、缓存兼容、补齐失败重试和并发场景；`node scripts/test-original-series-h5.cjs` 在本地 H5 开发服务上点击真实卡片，验证 `1 / 7` 至 `7 / 7`，最后回到封面。可用 `H5_URL` 指定开发服务地址。本次未修改字体路径、注册时机或绘制名称，尚未真机验收。CloudBase 登录返回 `AUTH_REQUIRED`，线上函数版本未能核对；本次未部署云函数。

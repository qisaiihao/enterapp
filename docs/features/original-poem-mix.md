# 原创诗歌混排

原创页默认每批加载 10 首，按「3 首新诗 → 2 首随机诗」排列两组。新诗按发布时间倒序，4 首插入诗歌由数据库从剩余候选中一次随机抽取。候选不足或抽样失败时，用剩余新诗补齐。作品总数不足 10 首时返回实际数量。

只展示可公开的原创诗歌，兼容 V1/V2 帖子。隐藏、删除、审核中、审核拒绝、活动帖子及已屏蔽作者（包括匿名作品的真实作者）在选取候选前排除。关注筛选、山页和其他列表保留原查询方式。

选择“随机刷新”后，每一批都从可见原创诗歌中随机抽取。再次点击或下拉刷新会开始新一轮抽取，选择“全部诗歌”可恢复默认混排。

## 分页与缓存

- `getPostList` 接收 `originalMix: true`、`isPoem: true`、`isOriginal: true` 才启用混排；有作者、标签、讨论或活动筛选时不启用。
- 全随机抽取使用 `randomPoems: true`，沿用相同的内容筛选与去重分页，每批直接查询数据库。
- 翻页通过 `excludePostIds` 传入本轮已经展示的全部诗歌 ID，服务端在剩余作品中选取，不使用固定 `skip`，避免插入旧诗后跳过新诗。刷新时重置为空数组。
- 首批继续与开屏预加载共享缓存，以 `originalMix:true` 后缀隔离旧时间序缓存。后续批次依赖本轮已读记录，直接查询，不跨刷新轮次复用分页缓存。
- 页面以请求序号丢弃刷新前的旧响应；缓存命中的列表重置也会使旧请求失效。

## 验证与发布

`npm run test:original-poem-mix` 覆盖混排位置、随机变化、点赞数变化、可见性、V1/V2 兼容、完整翻页、作品不足、抽样失败回退、缓存隔离及刷新竞态。这些测试已纳入 `check:quality`。

上线时部署 `functions/getPostList`（包含 `lib/poem-selection.js`）。已使用混排的客户端在下一次向服务端加载诗歌时应用新规则。

# 原创诗歌混排

原创页每批默认加载 10 首：6 首新诗、2 首高赞诗、2 首随机诗。排列为「3 首新诗 → 1 首高赞 → 1 首随机」重复两组。新诗内部按发布时间倒序，高赞诗按点赞数倒序（至少 1 赞），随机诗由数据库抽样；三组互相去重。候选不足或推荐查询失败时，以剩余新诗补齐，全部不足 10 首时返回实际数量。

只展示可公开的原创诗歌，兼容 V1/V2 帖子。隐藏、删除、审核中、审核拒绝、活动帖子及已屏蔽作者（包括匿名作品的真实作者）在选取候选前排除。关注筛选、山页和其他列表保留原查询方式。

## 分页与缓存

- `getPostList` 接收 `originalMix: true`、`isPoem: true`、`isOriginal: true` 才启用混排；有作者、标签、讨论或活动筛选时不启用。
- 翻页通过 `excludePostIds` 传入本轮已经展示的全部诗歌 ID，服务端在剩余作品中选取，不使用固定 `skip`，避免插入旧诗后跳过新诗。刷新时重置为空数组。
- 首批继续与开屏预加载共享缓存，以 `originalMix:true` 后缀隔离旧时间序缓存。后续批次依赖本轮已读记录，直接查询，不跨刷新轮次复用分页缓存。
- 页面以请求序号丢弃刷新前的旧响应；缓存命中的列表重置也会使旧请求失效。

## 验证与发布

`npm run test:original-poem-mix` 覆盖混排位置、随机变化、可见性、V1/V2 兼容、完整翻页、作品不足、推荐失败回退、缓存隔离及刷新竞态；已加入 `check:quality`。

发布时先部署 `functions/getPostList`（包含 `lib/original-poems.js`），再发布客户端。旧客户端未传 `originalMix` 时仍使用原有行为。自动测试不包含线上数据验证或手机真机验收。

# 收藏一致性

日期：2026-09-29。最低支持客户端为 1.7.0；本次收藏改动只涉及客户端，无需部署收藏云函数。

## 行为

- 收藏、取消一条收藏记录、删除收藏夹、创建及编辑收藏夹都通过 `api-cache/favorite-actions.js`。只有服务端成功才发一次 `favorite-changed`，失败保留原内容并允许重试。
- `utils/events.js` 在通知页面前统一调用 `cache/favorites.js`。清理当前用户的收藏分页、对应用户主页收藏缓存，以及受影响的详情缓存；没有收藏状态字段的首页列表不重拉。
- 删除会移动分页边界，因此该用户全部收藏页失效，前台收藏页重新读取第一页。后台页面标记待刷新，返回后读取；加载中的页面等旧请求退出再补一次刷新。
- 个人页原来永久有效、无账号前缀的收藏缓存改为按账号键存储，有效期 60 秒；不再读取旧的无账号分页键。刷新时仍立即失效，不等待 TTL。
- 读请求检查收藏版本和账号会话。账号切换、缓存清理或收藏变更后的旧响应不能写回缓存或页面；A→B→A 的旧写入也不会通知新会话。
- 同一帖子可以存在于多个收藏夹。删除指定 `favoriteId` 只删除该记录，不能据此广播 `favored: false`。详情页收到这种变更时移除过期的已知收藏标记，不编造跨收藏夹的总状态；现有服务端未提供总收藏状态查询，本次没有新增此查询或改变收藏按钮交互。
- 收藏夹删除提示与服务端行为一致：删除该夹及夹内收藏记录，其他夹中的记录保留。按夹 ID 移除本地行，避免刷新后数组下标变化误删另一行。

## 验证

`npm run test:favorite-loading` 包含原有列表、收藏菜单及封面测试，并新增 `test-favorite-consistency.cjs`。覆盖成功/失败、同帖多夹、分页边界、旧读响应、账号切换、公开收藏访客读取、后台页、事件合并，以及真实收藏夹页面加载器与分页 mixin 的 Vue watcher 联动。

收藏阶段完整 `check:quality`、App 和微信小程序构建通过。新增回归已纳入质量门禁。没有进行真机验收；需真机检查：详情收藏后返回个人页、从收藏菜单取消、同帖放入两个夹后移除其中一个、删除收藏夹后返回上级页、慢网中操作及切换账号。

## 兼容与边界

保持 1.7.0 已有云函数名称和收藏记录模型。没有迁移历史收藏数据，没有修改字体路径、注册时机或绘制名称。服务端并发写入及账号鉴权不在本项客户端一致性修改内。

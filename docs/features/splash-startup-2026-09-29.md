# 开屏与首屏预加载优化

2026-09-29。按用户最新要求调整开屏时序，保留打字机与淡出的视觉元素，进入按钮仅在慢加载时出现。

## 行为

- 打字机按固定节奏约 1.5 秒完整显示 `poementer`，不因快速加载提前补全文字或截断。
- 数据很快准备好时，打字完成后直接淡出，不显示按钮；加上 200ms 淡出，约 1.7 秒发起跳转。
- 数据较慢时等待首屏数据，准备好后用 200ms 淡出进入；例如 3 秒准备好，约 3.2 秒发起跳转。
- 自定义开屏最多等待 6 秒，包含淡出时间；认证或请求不返回也不会无限卡住。
- 打字完成但数据未就绪时显示进入按钮。点击立即发起导航，不再等待淡出或网络；连点和迟到请求不会重复导航。
- 加载明确失败时也保留按钮，未点击则第 6 秒自动进入，由页面现有加载流程继续处理。切页或卸载后取消动画定时器，防止旧页面抢回导航。
- 自动进入保留 200ms 透明度淡出，然后使用 `reLaunch` 无原生转场进入广场，避免 App 的 `switchTab` 用 `auto` 关闭非 Tab 窗口时额外向右滑动。手动跳过仍立即发起导航。
- 导航失败则恢复按钮供用户重试。

计时从自定义开屏的 `onLoad` 开始，不包括原生容器启动或系统路由渲染时间。JS 线程被系统挂起时也不能承诺严格的墙上时间；恢复后截止逻辑会立即执行。

## 首屏数据如何复用

开屏与诗歌广场使用相同的原创诗歌 API、相同的 10 条分页参数和同一个缓存键。开屏等待链路不再加载“山”页的 5 条数据，也不再加载已失效的 6 个 Tab 图标路径；山页和首页改为进入广场后后台预热。

列表准备好后，在内存中保留一份短期交接对象。广场 `onLoad` 同步接收并整理内容，将 `isLoading` 设为 `false`，不必先画骨架再等待一轮请求。交接同时支持真实空列表，并正确计算不足 10 条时的分页结束状态。

去掉了广场在命中新鲜缓存后 100ms 又强制请求第一页的逻辑。下拉刷新、发布/编辑后的刷新标记仍会使缓存失效并重新读取；关注筛选不会错误展示原创列表缓存。

交接对象按当前账号、缓存来源对象和 30 秒有效期检查，只允许领取一次；缓存被失效、账号变化或刷新标记存在时，页面使用常规加载流程。

## 请求与超时

### 进入广场后的其他 Tab 预热（2026-09-29 追加）

- 广场同步接收开屏数据后，或常规首屏加载结束后，调用 `scheduleTabPreload()`，延迟 800ms 启动。开屏动画、跳过按钮和 6 秒放行计时不等待它；尚未完成广场首屏加载时不会启动其他 Tab 请求。
- 每次应用运行只调度一次，不持有开屏或广场页面实例，切换 Tab 后继续执行。没有 openid 时跳过，账号变化后停止后续步骤和未开始的头像下载。
- 优先请求诗人列表 50 条，写入头像栏已有的 `poet:list` 缓存。按列表顺序预热头像图片，最多两个并发，先覆盖可见区域；本地路径仅保存在内存，最多 50 项，不写入持久化列表。
- 头像栏初始化时同步读取有效的诗人列表和已预热图片。预热尚未完成时仍使用原地址正常显示，不等待后台下载；本地文件被清理后先回退原地址，原地址也失败才显示默认头像。
- 诗人列表步骤结束后，顺序预取 mountain、index 第一页，各 10 条。头像下载独立继续，不阻塞两个列表。mountain 使用全部山诗、排除匿名的现有参数；index 按 `homeShowNormalPostsOnly` 保存的筛选偏好预取（默认全部帖子，普通帖获得 24 小时排序加成）。不预取关注、讨论子页或诗人筛选后的每个列表。
- 复用页面原有 API 和缓存键，页面提前打开时合并正在进行的相同请求，预热完成后命中原有缓存。列表中的云图片地址也在后台转换并缓存；此阶段不下载全部帖子图片，不修改持久化帖子对象。
- 后台列表请求静默执行，单步等待上限 8 秒，一步失败继续下一步；超时释放该后台请求的缓存任务，允许页面重试，迟到结果不会覆盖重试。头像单张等待 5 秒，超时停止对应下载 worker，避免未结束的底层图片任务继续累积。
- 字体注册仍由实际页面的 `onReady` 完成；后台预热不创建隐藏页面，也不提前注册其他页面字体。

本次后台预热修改已通过 `npm run check:quality`、`npm run build:app` 和 `npm run build:mp-weixin`（含包体积检查）。尚未进行本次修改的真机验证；建议冷启动进入广场后切换山页，检查诗人头像，再切换首页检查已保存筛选条件下的列表。

### 开屏请求

启动认证和列表请求共用 5 秒数据预算，列表读取支持可选 `timeoutMs` 和 `silent`。超时会结束缓存加载任务，释放去重记录，页面能够重试；原请求即使迟到，也不会把过时结果重新写入该缓存任务。

动画时限由独立控制器维护，不依赖这些 Promise 能否完成。若超过时限且没有可用数据，仍会进入页面，由页面继续加载；断网且没有缓存时不可能凭空显示内容。本轮保证正常成功路径进入即有内容，并避免异常路径困在开屏。

## App Tab 整页闪白优化（2026-09-29 追加）

用户反馈从原创广场切换其他 Tab 时，顶部栏和底部栏也会一起闪白。数据预热只准备接口与图片缓存，不会提前创建 App-vue 页面窗口。当前依赖中的 `_switchTab` 在首次访问时注册新 WebView，约 70ms 后调用显示；这不是目标页面已经绘制完成的保证。

自定义 Tab 栏通过 `utils/appTabTransition.js` 切换。首次打开目标页时，App 在路由前将当前页面截为内存 Bitmap，放到独立原生 View 中覆盖窗口交接间隙。2026-10-15 用户反馈首次进入仍闪白后，撤罩条件改为：目标页面 `onReady` 和路由成功之后，对目标 WebView 执行 `draw(..., { check: true })`，确认非空画面后再留出 32ms 交接时间。已确认就绪的 Tab 直接切换，不重复截图，使用 `onShow` 和 `$nextTick` 结束导航保护。这里不等待网络、图片或字体加载。

- 旧页截图最多等待 350ms，失败或超时仍使用符合当前主题的原生“正在打开…”过渡层；启用空白截图检查，迟到截图不重新显示。原生覆盖能力本身异常时才降级为平台路由。
- `View.show()` 没有完成回调，先让出 16ms 再检查显示状态；未显示时最多检查 160ms。覆盖层显式设置主题底色，并沿用源窗口的高度或上下边界约束。
- 目标非空检测失败时每隔 64ms 重试；冷切换最长保护 2400ms，已加载页面的导航保护上限仍为 1200ms。导航失败、用户返回、应用进入后台、目标卸载或其他页面显示时清理。截图与探测 Bitmap 不保存到文件，结束后释放内存。超时后的迟到 `onReady` 不会误将未确认画面的页面登记为可直接切入。
- 切换期间防止连续多次导航；重复点击当前 Tab 不重新切页，原双击刷新逻辑保留。导航失败恢复选中项。
- H5、小程序及没有原生截图能力的环境直接使用 `uni.switchTab`。
- mountain 和 index 在命中新鲜缓存时同步填充首帧，不再先清空列表再等待 Promise。首页后续继续补齐图片地址；山页按诗人区分缓存，刷新标记和下拉刷新会使缓存失效。
- 仍使用真实页面生命周期，字体管理器及 App `onReady` 字体注册方式保持不变。

实现依据：[HTML5+ WebView draw](https://www.html5plus.org/doc/zh_cn/webview.html#plus.webview.WebviewObject.draw)、[原生 View](https://www.html5plus.org/doc/zh_cn/nativeobj.html#plus.nativeObj.View)。原生 View 的 `show()` 显示于所有 WebView 之上，不能把过渡 View 附加到即将隐藏的源页面。App 的 `uni.preloadPage` 仅支持 nvue 页面，因此没有对现有 vue Tab 使用它：[页面预加载说明](https://en.uniapp.dcloud.io/api/preload-page.html)。

`scripts/test-tab-switch.cjs` 已纳入 `npm run test:splash`，覆盖首次与重复进入、导航和页面就绪的两种先后顺序、截图与首帧超时、导航失败、后台清理、连点、迟到回调、资源释放，以及缓存首帧、空列表、诗人筛选隔离和过期缓存。原生窗口合成和不同设备的实际观感仍需真机验收，自动测试不能证明已完全消除闪白。

本次整页闪白优化已通过完整 `npm run check:quality`、`npm run build:app` 和 `npm run build:mp-weixin`（含包体积检查）。建议在真机冷启动后立即切换“广场/读诗/我”，再反复返回切换，并检查浅色、深色及切换时退后台的情况。本次未进行真机验收。

## 底部导航响应与按压动效（2026-10-15 追加）

排查发现，卡顿不只来自按钮动画：三个帖子列表页在 `onShow` 校准点赞状态时，会调用兼容层遍历并持久化所有列表缓存。即使没有任何点赞变化，50 页缓存也会产生 100 次同步存储写入。另一个来源是已加载 Tab 仍重复截图，静态截图会冻结按钮动画，并额外等待交接。

- 页面显示只读取最新点赞状态并批量更新本页 UI，删除全缓存回写。实际点赞操作及变更事件继续同步内存与持久缓存。
- 按页面实例记录就绪路由；受保护的首次切入还需通过原生非空画面确认，再次切入直接导航。页面卸载清除就绪记录，旧实例卸载不能清除同路由新实例。取消、失败和超时释放资源与按钮导航锁，迟到回调不二次完成。
- Vue 与微信原生 Tab 保留立体图标和深浅主题。用户反馈选中时像凹陷后，移除选中内阴影及内层永久下移；选中只高亮图标、边框与文字，按钮保持浮起。通过 `hover-class` 在按下时立即反馈：80ms 整体下移 4rpx、缩至 0.96，松开后约 200ms 恢复浮起；切页不等待动画播完。
- 浮起和按下使用两层预绘制外阴影，通过透明度切换；连续动画使用 transform、opacity 和文字颜色，阴影不逐帧插值。支持系统减少动态效果设置。
- 每项点击热区扩展到栏宽的四分之一，图标仍保留原先居中间距；保留当前页双击刷新和未登录“我”的拦截，导航期间连点不误触刷新，失败还原选中状态。
- 字体路径、注册名称和页面 `onReady` 注册方式沿用原约定。

## 首启隐私政策确认（2026-10-09 追加）

- `onLoad` 先检查同意状态。已同意时开屏计时与预加载仍在 `onLoad` 同步启动，1.5/6 秒时序不变。
- 未同意时展示 `PrivacyConsentDialog`（`AppDialog` 居中样式），打字动画继续，但不创建开屏放行计时、不调用 `preloadPoemSquare`；确认前不会因 6 秒上限进入应用。
- 同意后写入 `privacyConsentVersion` 并启动预加载与放行计时，最短展示时长按已等待时间补足剩余部分，不重复等待 1.5 秒。
- 不同意时 App 退出、微信小程序退出；无法退出的环境提示后重新展示弹窗。
- App 启动引导（登录、更新检查、GitHub 深链）和未读/活动徽标初始化也由同一同意事件放行，1.5/6 秒开屏时序在同意后保持原有规则。
- 实现与验收说明见 [首启隐私政策确认](privacy-consent.md)。

## 维护入口

- `utils/splashGate.js`：最短、最长时长，退出过渡和一次性导航。
- `utils/splashPreload.js`：首屏请求、签名预热、缓存交接与失效检查。
- `utils/tabPreload.js`：广场首屏结束后调度 mountain、index 和诗人列表后台预热。
- `utils/poetAvatarPreload.js`：诗人头像限并发下载和本次运行内的临时图片复用。
- `utils/asyncTimeout.js`：可选异步超时。
- `api-cache/poems.js`：共用分页常量与缓存读取。
- `pages/splash/splash.vue`：动画呈现与导航。
- `pages/poem-square/poem-square.vue`：首帧同步消费和常规缓存读取。

开发日志 `[splash] content ready` 和 `[splash] leaving` 分别记录内容就绪耗时、离开原因和耗时。生产环境是否输出受现有日志开关控制。

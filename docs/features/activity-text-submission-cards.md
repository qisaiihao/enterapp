# 活动纯文字投稿卡片

2026-09-28：修复普通发布入口关联活动后，纯文字投稿在活动详情显示为白色普通帖的问题。

## 原因与规则

普通发布入口保存 `publishMode=normal`，即使关联活动或选择匿名发布，也不会转换为诗歌类型。原活动详情只对诗歌和组诗使用彩色卡片。

活动详情现在也对 `joinedActivityId` 匹配当前活动、正文非空且没有图片的普通投稿使用 `PoemCard`。保留背景色和文字色，复用展开、点赞、评论交互；公告、讨论和带图片的普通帖继续使用原展示。显式诗歌、组诗维持原规则。

此规则仅作用于活动详情，不改写帖子类型或匿名标记，不增加云函数调用。

## 历史数据与匿名

只读排查发现截图中的《废稿》正文帖存储为普通帖，作者显示名为“匿名用户”，但 `isAnonymous=false`。白色卡片直接由类型判断导致；历史匿名标记为何丢失尚未确定。本次没有修改线上数据，也不通过作者名推断匿名状态。

当前普通入口匿名发布的回归用例验证发布参数保留 `isAnonymous=true` 和活动关联。匿名诗歌卡片仍隐藏签名。该测试不等同于线上发布及真机验收。

## 验证与发布

- `npm run test:activity-cards`：历史数据回归、匿名/非匿名、公告/讨论/图片隔离、发布参数、卡片展开、点赞同步与失败回滚。
- `npm run check:quality`、`npm run build:app`、`npm run build:mp-weixin`。
- 本修复只涉及客户端，无需部署云函数；需更新 App 或小程序后生效。
- 真机复核：进入活动详情确认《废稿》为彩色卡片，展开正文、点赞、进入评论，并检查其他普通图片帖图片仍可见。

本次结果：活动卡片回归、App 构建、小程序构建及包大小检查通过，尚未真机验收。完整 `check:quality` 未通过：工作区中另有三个登录/短信文件混合换行符，以及 posts 共享模块副本未同步；本次未改动这些文件。编码检查之后的其余质量检查已单独运行，通过至 posts 同步检查处。

后续同日修复：混合换行符与共享模块同步已处理。用户确认《废稿》来自旧版未登录发帖的临时身份；正常账号匿名链路的进一步修复和云函数发布范围见 [匿名帖子链路](anonymous-post-chain.md)。上文无需云函数部署仅指活动卡片样式改动。

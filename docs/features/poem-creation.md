# 原创诗歌创作落款

原创诗歌发布预览页在标题、作者输入区下方靠右提供两条较短的横线输入框，用于选填创作时间、地点。文字靠右，字号小于标题和作者，底部横线与上方输入框一致。时间、地点均手动填写，最多各 40 字；填写即展示，清空即隐藏。修改后立即更新上方卡片，并同步到编辑草稿。活动按钮位于这两项下方。

卡片正文下方靠右展示落款，标准日期显示为 `2026.10.12`，其他时间文字保留原样；同时填写地点时显示为 `2026.10.12 · 杭州，窗前`。落款沿用汇文明朝和卡片文字色，使用较小字号与较低不透明度。作者签名排在落款之后。预览、诗歌列表、个人页、详情和分享图片采用相同展示选项。

草稿和已发布诗歌保留四个字段：

| 字段 | 内容 |
| --- | --- |
| `creationDate` | 创作时间文字，例如 `2026-10-12`、`2026年秋` |
| `creationLocation` | 创作地点 |
| `showCreationDate` | 是否展示日期 |
| `showCreationLocation` | 是否展示地点 |

时间与地点可以独立填写、独立清空。旧作品没有这些字段时不显示落款。非原创诗歌和其他发布类型不展示；已发布诗歌改为非原创时清除落款字段。创作时间独立于帖子发布时间。

## 发布与验证

随客户端发布部署 `contentCheck`、`createPost`、`updatePostContent` 云函数，包含各自的 `_lib` 目录和 `contentCheck/moderation.js`。共享帖子模块由 `scripts/sync-posts-shared.cjs` 同步，审核入口由 `scripts/sync-moderation-gate.cjs` 同步。

`npm run test:poem-display` 包含落款回归，覆盖展示选项、草稿、新建与修改、两种帖子存储格式、详情和分享图片换行与签名布局。项目检查使用 `npm run check:quality`，App 构建使用 `npm run build:app`。

# 举报与拦截内容复核

## 用户流程

帖子详情右上角「…」→「举报」进入举报页。用户先选择「对他人造成困扰或危害」或「侵犯我/我的组织的权益」，再选一个具体原因。补充说明最多 500 字；选择「其他问题」或「其他侵权」时必填。权益侵害类可附最多 3 张图片证据。提交成功后显示确认信息并返回帖子详情。

同一用户对同一帖子只能同时存在一条待受理举报。重复的网络请求由 `requestId` 去重。证据仅接受该用户上传到 `post-reports/<openid>/` 路径的云文件 ID。

## 管理员流程

管理中心 →「举报与复核」，在同一页面切换「举报」与「拦截复核」。两种来源各自保留状态筛选，原有 `reportId` 链接仍定位举报，`reviewId` 链接定位复核。

「举报」中的待受理、已删帖、不处理和全部四个列表提供帖子快照、举报原因、补充说明及证据图片。管理员可打开原帖，也可选择「删帖并处理」或「不处理」。删帖沿用现有管理员删帖逻辑，同时删除评论和收藏；处理结果、管理员 ID 和时间保存在举报记录中。帖子删除后，举报中的帖子快照仍供核查。

只有 `adminManager` 中既有的诗号管理员鉴权通过后才能读取和处理举报。用户提交也通过该云函数，但只开放 `submitPostReport`，不返回其他用户的举报数据。

## 被拦截内容的二次复核

开启 `CONTENT_MODERATION_MODE=enforce` 后，发布帖子（含讨论、组诗和拼贴诗）、编辑帖子、发布评论遇到自动审核的 `Review` 或 `Block` 结果时，由写入口把准备好的内容保存到 `moderation_review`，向用户返回「已提交管理员复核，通过后自动发布／生效」。自动审核服务故障、超时及输入超限仍返回失败，不能借人工队列绕过异常。

待复核的新帖和评论不会提前进入公开集合；被拦截的编辑保留原帖原内容。后台自动留存提交人、来源、完整快照、审核结果和请求 ID，以及供服务器重新执行写入的数据。同一提交人、来源和相同待写内容去重；已经拒绝的相同内容需要修改后重新提交。拼贴图进入待复核时保留对应云文件供管理员预览。

「拦截复核」提供待复核、已通过、已拦截和全部状态。展开详情后可以核查完整标题、正文、图片、高光句、组诗各段、讨论引用句和评论，并查看自动审核说明。管理员可填写最多 500 字的处理说明，确认「通过并发布」或「维持拦截」。通过后按原提交人的身份写入帖子、修改或评论；处理人、时间、说明和最终内容 ID 保存在复核记录中。

最终写入、队列状态更新及结果通知在同一个事务中完成，重复审批不会重复发布。通过前重新检查账号、发帖限制、原帖／引用帖／父评论及活动状态；编辑若原帖内容已变化，需重新提交，不能覆盖后续修改。被拒绝的新内容不发布，被拒绝的修改不影响原帖。

复核的列表、详情和处理 action 都需管理员鉴权。普通用户通过发布入口得到自己的队列状态和结果消息，不能直接读取后台复核记录，也不能自行提交「已审核」载荷。

账号注销时，删除该账号提交的复核记录及其中尚未公开的内容，保留其他账号的复核记录。复核引用的图片可能同时用于现有帖子，不能据此批量删除图片文件。

## 消息通知

举报提交成功时，系统向当前配置中的每位管理员写入「某某提交了新的举报」消息；管理员点击后直达该举报详情。管理员删帖并处理后，举报人收到「某某处理了您的举报」；选择不处理后收到「某某没有通过您的举报」。举报人点击结果消息可查看帖子标题、举报原因及处理结果。消息页「举报」标签汇总这三类通知，全部消息页也会展示。消息与举报的创建或处理结果写入同一次数据库事务，重试不会重复发送同一阶段的通知。

复核队列创建后，每位管理员收到 `content_review_new`；点击消息直达该条复核，并重新确认管理员权限。提交人收到 `content_review_approved` 或 `content_review_rejected` 结果消息。消息页「复核」标签汇总这三类通知；通过消息可打开已发布帖子（评论则打开所属帖子），拒绝消息仅展示结果。普通提交人不会被结果消息引导进入后台详情。

## 上线准备

1. 在云数据库创建 `post_reports`、`moderation_review` 集合。`moderation_review` 禁止客户端直接读写，服务器通过管理员 action 读取与处理。举报索引：`status` + `createTime`（降序）、`reporterOpenid` + `postId` + `status`；复核索引：`status` + `createTime`（降序）。消息筛选需已有 `toUserId` + `type` + `createTime`（降序）索引。如平台提示其它复合索引，按实际查询添加。
2. 保持审核 `off`，运行共享副本同步脚本，部署整个函数目录及依赖：`contentCheck`、`createPost`、`createDiscussionPost`、`addComment`、`updatePostContent`、`uploadCollagePoetry`、`adminManager`、`getMessages`、`cancelAccount`。`contentCheck` 同时负责诗歌的发布入口；只部署审核 API 或管理页不能完成复核链路。保留线上私有环境变量和已有配置。
3. 发布 App / 微信小程序，确认管理入口、两类列表和消息筛选可用。配置审核密钥及套餐，最后将 `CONTENT_MODERATION_MODE` 切为 `enforce`。用测试账号验证文本和图片拦截、待复核不公开、通过自动发布、拒绝保留拦截、重复审批、多人同时处理、评论计数／通知、原帖修改冲突及非管理员访问。
4. 回滚需配套回退客户端和云函数，保留历史举报／复核记录。先关闭审核只能停止新拦截；已有待复核任务仍需按管理策略处理。

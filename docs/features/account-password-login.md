# 账号密码登录

登录页支持用户名（现有 `nickName` 昵称）、Poem ID、已绑定手机号搭配密码登录。

客户端向 `loginWithCredentials` 传入 `account` 和 `password`。服务端按 Poem ID → 手机号 → 昵称的顺序精确查询，去除账号首尾空格，保留大小写。命中某类账号后才验证密码，不会因密码错误继续匹配其他用户。

昵称不要求唯一。若同类标识命中多个用户，返回 `AMBIGUOUS_ACCOUNT`，提示使用唯一的 Poem ID 或绑定手机号，不根据密码在重名用户中选择。若昵称与其他人的 Poem ID 或手机号相同，优先识别 Poem ID、手机号，该昵称用户需使用自己的 Poem ID 登录。

旧客户端和 GitHub 绑定流程仍可传入 `poemId`、`password`，保持只按 Poem ID 验证。微信绑定提示、登录后的手机号绑定和会话处理沿用现有流程。

验证命令：`npm run test:login`。

发布时先部署腾讯云函数 `functions/loginWithCredentials`，再发布客户端。新客户端使用 `account` 参数，依赖新版云函数；旧客户端可继续调用新版云函数。

## App 新账号注册手机号绑定（2026-10-11）

新版 App 注册必须先通过本机号码一键授权或短信验证码验证手机号。一键授权未完成时切换到短信绑定；绑定弹窗提供“取消”，关闭后返回注册表单，不提交注册。验证期间 App 锁定输入和弹窗关闭，注册保存本次实际验证的号码。提交注册和跳过绑定方法均有 App 检查，未绑定时不会调用注册云函数。GitHub 新用户完善资料也进入同一注册页面，适用同一规则。

网页版保留手机号绑定弹窗及“跳过”，小程序仍可直接注册。已有账号的登录和会话恢复不增加强制绑定要求；原有登录后提示仍可选择“稍后再说”。

该限制在新版 App 注册页面执行，云函数接口和旧客户端行为未修改。本次随客户端发布，无需重新部署云函数。`npm run test:login` 包含注册平台差异、绑定取消及失败、绑定后注册和已有账号延后绑定的回归测试；本机号码授权、真实短信收发及真机注册流程仍需发布前验证。

## 手机短信验证码登录

登录页可切换“密码登录”和“验证码登录”。验证码登录使用已绑定的中国大陆手机号和 6 位短信验证码，不需要密码。未注册或未绑定的号码会提示先注册；不自动创建新账号。手机号绑定多个账号时，提示改用 Poem ID 和密码。

客户端调用 `sendSmsCode({ phone, scene: 'login' })` 发送，再调用 `loginWithPhone({ phoneNumber, code })` 登录。登录云函数自行验证并消费验证码，不能先在客户端调用 `verifySmsCode` 再直接提交手机号。绑定、修改手机等场景的验证码不能用于登录。

登录验证码使用随机数生成器生成，带随机盐的摘要存入 `sms_codes`；不使用配置中的固定测试验证码。5 分钟有效，成功后不可重用，连续输错 5 次需重新获取。验证和消费使用数据库事务，并发请求最多登录成功一次。发送成功前的验证码不可用，重新发送会使上一条验证码失效。

为兼容旧版云函数 Node.js，服务端使用 `require('crypto')`，验证码通过 `randomBytes` 和拒绝采样生成，不依赖 `node:` 导入或 `crypto.randomInt`。登录测试包含这两项能力缺失的模拟环境。

登录发送使用独立事务配额：同号码 60 秒一次、24 小时窗口最多 10 次；可获取真实客户端 IP 时，同 IP 1 小时窗口最多 50 次。发送失败也占用配额。手机号、IP 配额记录不设置 `expiredAt`，验证码 TTL 清理不影响配额。

发布顺序：部署 `sendSmsCode`（包含 `login-sms.js`）、`loginWithPhone` 后再发布客户端；若密码登录改动尚未上线，同时部署 `loginWithCredentials`。沿用现有腾讯云短信环境变量 `TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`、签名及模板配置。`sms_codes` 和 `sms_logs` 集合需存在，验证码集合必须禁止客户端直接读写，只允许服务端云函数访问。短信服务、模板可用性、数据库权限及真实短信收发需在部署环境验证。

## 找回密码

登录页的灰色下划线“找回密码”入口使用已绑定手机号、6 位短信验证码、新密码及确认密码。新密码要求 6–32 位且首尾不能有空格。成功后返回密码登录，预填手机号并清空密码字段，由用户使用新密码登录。

发送调用 `sendSmsCode({ phone, scene: 'resetPassword' })`，提交调用 `resetPassword({ phoneNumber, code, newPassword })`。找回密码与登录验证码分别存储并强制校验场景，共用手机号与 IP 的发送配额。5 分钟有效、最多输错 5 次；登录、绑定验证码及旧版明文验证码均不能用于重置。前端通用云函数调用日志会隐藏密码和验证码。

服务端仅根据绑定手机号定位账号，忽略请求中的用户 ID 和 openid。不存在账号或手机号绑定多个账号时拒绝重置；事务内再次检查当前绑定手机号。修改密码和消费验证码在同一事务中提交，失败时一起回滚，禁止重复或并发消费。

密码保存沿用现有 `users.password` 字段，兼容现有密码登录接口；本次不迁移全站密码存储格式，也不撤销其他设备已有的本地登录状态。无法接收已绑定手机号短信的账号，需通过已有可用登录方式或管理员处理，不能只凭昵称或 Poem ID 重置。

上线先部署更新后的 `sendSmsCode`（含 `login-sms.js`），再部署新增 `resetPassword`（安装依赖），最后发布客户端。`cloudbaserc.json` 已加入新函数。验证命令仍为 `npm run test:login`，包含重置后新旧密码登录、跨场景拒绝、事务回滚、并发消费、重名手机号、前端确认密码及日志脱敏测试。真实短信和真机流程需部署后验证。

## 编辑主页设置和修改密码（2026-10-28）

编辑主页的 POEM ID 行最右侧提供带下划线的“修改密码”入口。打开时调用 `updateUserProfile({ action: 'getPasswordStatus' })` 查询当前账号的密码状态，仅返回 `hasPassword`。无密码时填写新密码、确认密码直接设置；已有密码时还需填写并验证原密码。新密码要求 6–32 位且首尾不能有空格，两次输入必须一致。密码单独保存，不提交或清除尚未保存的主页资料。

提交调用 `updateUserProfile({ action: 'updatePassword', mode: 'set' | 'change', oldPassword?, newPassword })`。云函数沿用当前跨端资料接口的账号标识方式，事务内重新读取当前状态；首次设置不能覆盖其他请求刚设置的密码，修改必须验证数据库中的原密码。状态冲突时切换对应表单并清空密码，由用户重新输入。密码状态加载失败时禁止提交，关闭或卸载页面后忽略迟到响应；保存期间防止重复提交和关闭弹窗。原密码、新密码均在通用调用日志中脱敏。

普通 `updateUserProfile` 资料保存不再接受 `password` 等密码字段，返回 `PASSWORD_ACTION_REQUIRED`，需使用上述专用 action。密码存储继续兼容 `users.password`；仅有未知 `passwordHash` 的账号需使用登录页短信找回，不能当作无密码直接覆盖。

发布时先部署 `functions/updateUserProfile`（包含新增的 `password.js`），再发布客户端，无需新增云函数或数据库集合。验证命令：`npm run test:profile-password`，同时已纳入 `npm run test:login` 和 `npm run check:quality`。自动测试包含前端两种表单、失败重试与请求失效、服务端原密码校验、首次并发设置和日志脱敏；真机设置、修改及新旧密码登录仍需部署后验证。

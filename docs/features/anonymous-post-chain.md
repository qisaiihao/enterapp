# 匿名帖子发布与显示链路修复

2026-09-28。

## 已确认的问题

- 编辑匿名帖时，add 页构造的预览数据未传递匿名标记，preview 保存又默认传 false。现在传递原标记，并从编辑原帖补全旧预览数据。
- 普通内容编辑不再取消既有匿名状态。服务端兼容旧客户端漏传或传 false；匿名状态变更为公开身份不属于普通编辑功能。
- createPost 的旧存储路径会保留真实 `_openid`，且可能保留作者署名。现在与 contentCheck 一样存匿名占位 ID、默认头像、匿名名称和服务端确认的 realAuthorOpenid，不保存签名。
- contentCheck 规范化布尔标记，并拒绝发布者 ID 无对应用户记录的请求，避免产生无归属帖子。匿名发布仍要求正常登录。
- 共享 posts 层统一处理旧数据匿名标记、内部所有权和公开信息；公开响应移除 realAuthorOpenid，隐藏真实 ID、头像、签名及旧作者快照。
- 详情页以服务端 isAuthor 判定匿名帖归属；匿名帖子不查询关注关系，不跳转作者主页。普通卡片和详情署名也显式处理匿名显示。
- 详情缓存按帖子和账号隔离，避免换号后沿用另一账号的 isAuthor；列表预填充不能代替详情权限查询。同账号仍复用缓存，更新与评论计数同步覆盖所有账号键。
- 旧匿名帖不再通过作者主页、关注流和关注用户的最近发帖时间暴露归属，过滤发生在分页/聚合前。

## 《废稿》历史记录

只读检查发现它保存为普通帖、isAnonymous=false，没有 updateTime，也没有能匹配用户表的作者归属。用户随后确认其 ID 是旧版未登录发帖生成的 anonymous_ 临时身份，登录弹窗问题已在其他改动中解决。因此不能把它当作“正常账号匿名帖编辑后丢标记”的证据，也不应猜测或迁移到某个真实账号。本次没有修改该线上记录。活动页的纯文字卡片兼容修复继续适用。

## 自动验证

`npm run test:anonymous-posts` 在内存数据库中执行实际云函数及前端方法，覆盖 V1/V2 存储、普通/诗歌/讨论发布、匿名标记、服务端所有权、活动关联、编辑保持匿名、未授权编辑拒绝、公开返回、旧数据、账号隔离缓存，以及 add → preview → contentCheck → getPostDetail → updatePostContent 的完整路径。它不会创建线上测试帖子。

作者主页分页回归还覆盖旧匿名帖不能占用访客可见分页名额。

运行 `npm run check:quality`、`npm run build:app` 和 `npm run build:mp-weixin`。自动测试不能代替 App/小程序真机发布、编辑、切换账号验收。

本次执行结果：完整质量检查、匿名链路回归、登录/短信回归、App 构建、小程序构建及包大小检查均通过。小程序主包估算 1.508 MiB。尚未进行真机验收或线上发布。

## 发布范围

这次包含服务端改动，不能仅更新客户端。之前“无需部署云函数”仅适用于调用量优化和活动卡片样式修复。

发布入口/编辑：contentCheck、createPost、updatePostContent。

作者关联查询：getUserProfile、getFollowingPosts、getFollowingUsersWithUpdate。

共享隐私处理：`functions/_shared/posts/consumers.json` 是部署包清单，共 45 个（含网站 webReader）。`npm run sync:posts` 已将匿名返回和所有权修复同步到各包的 `_lib/posts`；需随实际使用的帖子读取/写入云函数一起部署，特别是 getPostDetail、getPostList、搜索、推荐、个人资料与收藏接口，避免遗漏旧接口。部署包需要包含 `_lib/posts`，不是只上传 index.js。

无需数据库迁移，也不要为了本修复切换 POSTS_WRITE_SCHEMA；两种存储格式均有测试。当前工作区包含其他未发布功能，正式部署前需一起核对发布范围。本次未执行线上部署。

客户端需重新发布 App/小程序。换行符混用和共享模块副本不同步的问题已一并修正。

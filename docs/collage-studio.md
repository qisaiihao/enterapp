## 已实现的流程

1. 导入相册图片或拍照，生成最长边不超过 2560 px 的工作图，保存至本机。微信小程序的 `wx.getImageInfo` 返回不含 EXIF 旋转的原始宽高，导入时会按 `orientation` 交换横竖尺寸后再生成工作图，避免竖拍照片被压扁（仅微信小程序端，App/H5 保持原行为）。
2. 手动模式：单指拖动框选、拖动四角调整、移动选区；双指开合以两指中点缩放图片（100%–300%），双指同向滑动移动图片，也可以同时缩放和平移。第二根手指落下会撤回本轮单指框选或调整，保留手势开始前的选区；双指操作结束后剩余单指不会误触框选，全部松开后可继续框选。原有放大滑块和切换按钮保留（文案缩短为「移动/框选」），同一行新增「旋转」按钮，每次把工作图顺时针旋转 90° 并重置当前框选与缩放；若该原图已识别过文字，旋转前先清理对应的云端文件和缓存，已剪好的纸片和画布不受影响。滑块拖动时实时更新，有选区时以选区中心缩放，无选区时以当前可见画布中心缩放。「移动」模式支持单指平移和双指缩放。选区始终保持对应的原图坐标；图片移动后继续缩放会沿用当前位置，接近图片边缘时限制平移范围，避免露出额外空白。缩放和平移改为对固定尺寸的图层做 CSS transform，不再逐帧改变图片尺寸或滚动容器，以避免真机上双指操作时的闪烁。
3. OCR 模式：切入「识字选取」即自动识别，已有结果直接复用；此模式下导入或选择另一张原图也自动识别。失败时可点「重试识别」，不会自动重试付费请求。隐藏大幅原图、框选/放大控件及「从文字中挑选」标题和说明，保留原图缩略图用于切换、删除。按行展示文字，单字点一次即选中，再点一次取消；选段时依次点击同一行未选中的起始字和结束字，或直接选整行。再次点击任一高亮字会取消包含它的已选片段（重叠片段也一并取消），其余片段保留。可以连续选择同一张原图中的多段文字，已选列表支持单独取消、清空和点击切换预览。点击「一次制作 N 张」逐段生成独立素材，共用当前留白和边缘样式，每段撕边保留独立随机种子；保存失败时保留已成功素材，剩余片段可重试，不重复保存。切换原图时清空待制作列表。已移除「看原图」按钮。
4. 手动模式直接按框选范围裁切，不提供留白设置；识字选取默认留白 6 px，可在 0–48 px 范围调整。框选松手、选字或整行、切换已选片段后自动生成预览；修改留白、边缘样式也自动更新，已移除「预览纸片」按钮。预览经过短暂合并避免连续选择重复绘图，不阻塞下一次选择，并丢弃过期结果；原生 Canvas 的预览与保存/OCR 裁图串行执行。切回手动模式时不会沿用识字模式的留白。选择直切、剪纸或撕纸边缘，保存透明 PNG 纸片。
   已移除纸片命名输入框和素材库中的纸片名称、重新裁切；素材库卡片只保留「放到画布」和「删除」两个图标按钮（add/delete 图标，靠右排列）。
   撕纸边缘在新框选、重新选字或制作下一张纸片时随机变化，也可点击「换一种撕边」生成新的预览。同一张纸片的预览与保存使用相同边缘，已保存的纸片不会随之改变。
   新版撕边采用连续噪声轮廓、半透明细纤维和窄幅浅色断面，文字中央保持清晰。像素处理依赖 `canvasPutImageData`，微信开发者工具不支持该 API（报 `canvasPutImageData:fail 开发者工具暂时不支持此 API 调试`），此时自动改用轮廓撕边并在控制台告警，预览和保存仍可继续；真机使用像素撕边。源码参考、版本兼容和像素处理说明见 [撕纸边缘实现与来源](collage-paper-effect.md)。
5. 素材库可反复使用纸片和删除素材。官方素材库按分组组织：素材库标签页的「官方纸片」和画布背景菜单的「使用素材库」都会打开两步选择面板（先选分组、再选素材，交互参考诗歌卡片配色选择），选中后下载到本机素材库并使用。官方素材按次导入本机，之后的移动、缩放、导出和离线使用与自剪纸片一致，管理员删除云端素材不影响用户已导入的副本。
6. 在 900 × 1200 的画布中拖动、缩放、旋转纸片，支持后退和前进。底纸颜色、置顶、置底和删除位于同一行；未选中纸片时，置顶、置底和删除置灰。
7. 画布下方为「下载」和「发布」两个按钮，不再需要单独的导出步骤。下载按当前画布生成 900 × 1200 的 PNG 并直接保存到本地（App/小程序存入相册，H5 下载为文件）；发布生成同样的图片后传给现有拼贴诗上传页，用户点击该页发布按钮后才会发布为拼贴诗。每次操作都重新生成图片，生成的作品图显示在按钮下方供预览。

素材和画布草稿按当前登录账号在本机隔离；未登录时使用本机访客空间。App/小程序使用持久文件，H5 使用 IndexedDB 保存图片，不把临时地址写入草稿。

可以连续导入多张原图，通过缩略图切换。每张缩略图右上角的小「×」用于删除该原图，删除前会确认。删除其它缩略图不会切换当前选中的原图。已剪好的纸片和画布仍保留，仍能用于拼贴、导出和发布。

纯手动导入的图片只保存在本机，删除不需要网络。曾提交 OCR 的原图会先清理对应的云端临时文件、原图索引和识别缓存，再删除本机原图。云端失败时保留原图和清理记录供重试；同一内容仍被另一张原图引用时，保留共享缓存，删除最后一份引用后清除。已消耗的识别次数计数不随原图删除而减少。

上传前将云端归属和清理标记保存至本机，并在云端登记原图，便于清理失败上传。旧版已识别的原图没有缓存索引时，会临时上传本机原图来定位并删除旧缓存，不调用 OCR；本机旧文件缺失或云端身份发生变化时会提示，避免把未完成清理当作删除成功。

本版不提供跨设备素材同步。卸载应用、清理应用数据或浏览器站点数据会删除本机素材。导入工作图会经过缩放和 JPEG 编码，需保留相册原图用于更高分辨率的后续制作。

## 官方素材库

官方素材库为所有用户提供管理员上传的纸片和背景，按分组组织。用户端入口为工作台「素材库」标签页的「官方纸片」和画布背景菜单的「使用素材库」，两者都打开两步选择面板：先选分组（显示分组名和最多 3 张缩略图），再选具体素材；纸片和背景各自维护独立分组。背景素材为高:宽 4:3 的竖版图，选择背景时缩略图框保持同样比例，分组预览一行最多 3 张、具体素材保持一行 2 张；纸片仍使用原有的横向预览框。

前端：`components/OfficialMaterialPicker.vue`（两步选择面板，交互与 `ColorPickerModal` 一致）、`api-cache/collage-materials.js`（公开分组列表，5 分钟内存缓存，用 `fileUrlCache` 换取临时 URL）、`utils/collage/official.js`（下载并保存到本机后再使用）、`pages-admin/collage-material-management/collage-material-management.vue`（管理页）。

云函数：

- `functions/getCollageMaterials/`：公开只读，`action: list`，可按 `type`（`paper` / `background`）过滤，返回 `groups`（分组内嵌素材，未分组素材排在最后的“未分组”桶）和扁平 `materials`；素材最多 200 条，按创建时间倒序。
- `functions/adminManager/` 新增素材与分组管理：`listCollageMaterials`、`createCollageMaterial`、`updateCollageMaterial`（重命名或移动到分组）、`deleteCollageMaterial`、`listCollageMaterialGroups`、`createCollageMaterialGroup`、`renameCollageMaterialGroup`、`deleteCollageMaterialGroup`，沿用现有管理员校验；删除素材时同时清理云存储文件，分组下还有素材时不允许删除分组。

数据表：`collage_materials`（`type`、`name`、`fileID`、`groupId`、`width`、`height`、`createdAt`、`updatedAt`、`createdBy`）和 `collage_material_groups`（`type`、`name`、`sort`、`createdAt`、`updatedAt`、`createdBy`）。客户端不直连数据表（ACL 为仅服务端），上传图片存放在 `collage-materials/<paper|background>/`。云存储需保持“所有用户可读”（默认规则即可），否则普通用户无法换取素材临时链接。

管理页限制：单张图片不超过 5 MB，最长边不超过 2560 px，支持 JPG/PNG/WebP；纸片建议使用透明 PNG。素材名称最多 24 字（可在素材卡片上重命名），分组名称最多 16 字且同类型内不能重名。云函数会再次校验类型、名称、尺寸、`cloud://` fileID 和分组归属，客户端校验只用于提前提示。

部署命令（使用本机已登录的 CloudBase CLI）：

```powershell
node scripts/manage-collage-materials.cjs setup
tcb fn deploy getCollageMaterials
tcb fn deploy adminManager
node scripts/manage-collage-materials.cjs inspect
```

`setup` 创建两张数据表并设为仅服务端访问。管理员在「管理中心 → 拼贴素材」创建分组、上传素材、移动素材后即可在用户端看到；用户端列表有 5 分钟缓存，管理页增删改后会立即失效本机缓存。

H5 端导入官方素材使用 `fetch` 拉取临时 URL，需要在云存储配置 CORS（见 [云存储 CORS 配置指南](deployment/cors-config-guide.md)）；App 和微信小程序使用 `uni.downloadFile`，不受 CORS 限制，但正式版需把云存储域名加入小程序的 downloadFile 合法域名。用户端每次选择官方素材都会下载并保存到本机，因此官方素材不宜过大。

## OCR 接入与迁移边界

前端：`api-cache/collage-ocr.js`。

云函数：`functions/collageOcr/`。

云端接口为 `GeneralAccurateOCR`，启用 `IsWords=true`、`ConfigID=OCR`、`EnableDetectSplit=true`。使用 SDK，运行区域固定为中国大陆广州。

统一返回结构：

```text
schemaVersion / provider / model / width / height
lines[]
  id / text / confidence / polygon
  chars[]
    text / confidence / polygon
```

所有坐标对应上传的同一张工作图。使用原图四点坐标，不混用旋转纠正后坐标；缺少单字坐标或文字对齐失败时，只提供整行选择和手动调整，不假设每个字等宽。

从手动模式切入「识字选取」时，有框选就仅上传该矩形内的 JPEG（不添加留白、撕边或额外缩放），无框选就上传整张工作图。区域的任一边小于 15 px 时在本机提示扩大选区，不上传或调用 OCR。局部识别结果的行/字四点坐标均加回裁切偏移，制作素材时仍从原始工作图裁切。手动识别范围与之后的文字选区分开保存，重复切换标签不会把某段已选文字误当成新的识别范围。

整图识别结果仍保存在 `source.ocr`；每个不同矩形保存在父原图的 `source.ocrRegions[]`，拥有独立上传 ID、清理引用和识别结果，避免整图/局部结果互相覆盖或漏删云端缓存。重复进入相同范围直接复用本机结果，改变范围会清空此前待制作的文字片段。删除原图时，先逐个清理区域的云端文件和缓存，再清理整图记录；任何一步失败都保留本机原图以便重试。此功能沿用现有云函数接口，只需更新前端。

以后切换百度或自部署，只需更换云端识别调用和结果适配，保持上述返回结构。裁切、素材库和拼贴画布可继续使用。迁移时更新缓存版本，避免不同模型结果混用。

## 云端部署

环境：`cloud1-5gb0pbyl400845f5`。

函数：`collageOcr`，Node.js 18.15，60 秒超时。

数据表：`collage_ocr_usage`、`collage_ocr_cache`，均设为仅管理端/云函数访问。

角色：`PoementerCollageOcrRole`，沿用该函数原有 CloudBase 基础权限，额外策略 `PoementerCollageOcrInvoke` 只允许 `ocr:GeneralAccurateOCR`。未修改其他函数共用的 `TCB_QcsRole`。

使用运行角色提供的临时凭证，无需把永久密钥写入代码或客户端。若其他部署环境确需独立密钥，后端支持 `OCR_SECRET_ID`、`OCR_SECRET_KEY`；不要提交到仓库或放进前端。

部署/检查命令（使用本机已登录的 CloudBase CLI）：

```powershell
npm ci --prefix functions/collageOcr
node scripts/manage-collage-ocr.cjs setup
tcb fn deploy collageOcr --config-file cloudbaserc.collage.json
node scripts/manage-collage-ocr.cjs setup-role
node scripts/manage-collage-ocr.cjs inspect
node scripts/manage-collage-ocr.cjs inspect-role
node scripts/manage-collage-ocr.cjs health
```

`setup-role` 应在首次函数创建后执行。首次在全新环境部署时，先去掉配置中的角色字段，待角色创建完成再恢复。当前环境的数据表、专用角色及 OCR 权限已只读核验，无需重复执行 `setup` 或 `setup-role`。仓库配置现在会在部署后启用 OCR。

`health` 不调用 OCR；管理端直接调用没有终端用户身份，预期返回 `AUTH_REQUIRED`，用于确认函数能加载且不接受伪造的 `event.openid`。

## 本次启用步骤（由用户部署）

在项目根目录运行：

```powershell
tcb fn deploy collageOcr --config-file cloudbaserc.collage.json
node scripts/manage-collage-ocr.cjs inspect
```

确认 `COLLAGE_OCR_ENABLED` 为 `true`、运行角色为 `PoementerCollageOcrRole`。新版须包含 `index.js`、`core.js`、`store.js`、`provider.js` 和 npm 依赖。CLI 配置会安装依赖；若从开发工具上传，选择云端安装依赖。不要只启用旧函数，否则前端的 `prepare` 上传登记及删除协议可能不匹配。

若部署工具未同步配置，运行 `node scripts/manage-collage-ocr.cjs enable` 可单独启用 OCR 并将超时设为 60 秒，保留其它环境变量，不重新部署代码；之后运行 `inspect` 核验。

也可在 [CloudBase 云函数控制台](https://console.cloud.tencent.com/tcb/scf?envId=cloud1-5gb0pbyl400845f5&rid=4) 上传新版代码，选择 `collageOcr`，把环境变量 `COLLAGE_OCR_ENABLED` 从 `false` 改为 `true`，保存配置。使用现有运行角色提供的临时密钥，不需要在客户端填写 SecretId 或 SecretKey。

之后在 App 中登录，进入工作台，导入一张清晰书页，切入「识字选取」自动识别。检查文字、单字选区、裁片内容和保存结果。

没有额度或服务不可用时，界面会提示并保留手动框选功能。源码中的识别调用不自动重试，避免超时后重复扣费。

## 使用次数与缓存

- 每月上限默认 1000 次，环境变量 `COLLAGE_OCR_MONTHLY_LIMIT` 可调低，代码不会接受高于 1000 的值。
- 默认每个云端身份每天 20 次，可通过 `COLLAGE_OCR_DAILY_LIMIT` 调整。
- 月份和日期按北京时间计算。
- 使用数据库事务先预占一次额度，并发请求不会越过上限。
- 对同一身份、相同工作图内容的成功识别结果做缓存；重复选字、裁切、换边缘不调用 OCR。
- 成功缓存不受新请求额度限制；失败或尚在处理的相同图片有 5 分钟冷却期。
- 失败和超时的尝试也保守计入本工具上限，因为部分服务端失败可能计费。
- 这是本工具自身的请求上限，**不是腾讯云真实剩余免费额度查询**。同账号的其他工具调用、免费包是否到账、后付费设置仍以腾讯云控制台为准。
- 临时识别图片位于 `collage-ocr/<云端身份摘要>/`，云函数处理后尝试删除。上传前在 `collage_ocr_cache` 中登记 `kind: source` 的原图索引；删除原图时按索引重试清理残留文件，并移除对应索引和无其它引用的缓存。识别结束时通过请求标识校验，防止迟到响应重新创建已删除的缓存。

App/H5 沿用项目当前 CloudBase 登录方式：后端按运行上下文中的 CloudBase UID 限制每日次数；该 UID 若为匿名云身份，不等同于业务账号。全局每月上限仍统一生效。

## 日志排查

拼贴诗全流程统一使用 `utils/collage/debug.js`，日志前缀为 `[拼贴诗][模块]`，模块包括 `main`、`compose`、`square`、`upload`、`studio`、`canvas`、`storage`、`ocr`、`list`。

## 第一版的边界

- 手动裁切为矩形选区，纸片外观可应用不规则边缘；不包含自由套索。
- 每张 OCR 纸片对应一行中的连续文字或一整行；可将跨行、同一行中不连续的多段文字一次制作成多张独立纸片，不将跨行文字拼成同一张裁片。
- 不自动拉平弯曲书页，也不自动把倾斜文字旋正。
- 单张画布最多 60 张纸片，导出尺寸固定为 900 × 1200；素材 PNG 最长边不超过 1600 px。
- 当前工作台保留一份自动保存的本机画布草稿。

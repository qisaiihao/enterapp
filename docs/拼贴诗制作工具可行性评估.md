# 拼贴诗制作工具可行性评估

评估日期：2026-09-23

## 一、结论

**能做到，两种模式都有明确的实现路径。** 手动框选难度较低；OCR 选字裁切难度中等，关键在于文字定位精度和选择体验。适合先围绕清晰的书页、试卷做出可用版本。

这个设想最有价值的地方，是**保留文字原本的字体、纸张纹理和印刷痕迹**，让最终素材看起来就是从原纸上剪下来的。

## 二、手动框选模式

实现把握高，流程可以是：

上传图片 → 放大、移动图片 → 框选区域 → 调整边缘和留白 → 加入素材库。

第一版做可调整大小的矩形框就够用，可以剪文字，也能剪插画、批注。自由套索和复杂轮廓可以后续增加。

需要注意的是，屏幕上显示的是缩小预览，实际裁切必须对应到原图像素，才能保证素材清晰。

## 三、OCR 选字裁切模式

可行，核心是拿到每个字的位置。

例如图片里有一行：

> 风从遥远的山谷吹来

用户在识别文本中选中“遥远的山谷”，程序找到这些字在原图中的坐标，裁出包含它们的纸片，再加入素材库。

这里需要 OCR 同时返回：

- 识别出的文字；
- 文本行的位置；
- 单个字的位置。

现成接口已经支持这些能力。例如腾讯云通用文字识别高精度版支持请求单字信息，其数据结构提供单字在原图中的四点坐标。因此这个关键环节有现成技术可用，无需从头训练模型。参考：[接口说明](https://cloud.tencent.com/document/api/866/34937)、[坐标数据说明](https://cloud.tencent.com/document/product/866/33527)。

不过，**接口支持不代表任何照片都能精准裁切**，还要用实际书页和试卷验证。

建议交互采用“按行展示、逐字可选”：点击起始字和结束字，原图同步高亮对应区域，允许微调后保存。这样也方便处理同一页重复出现的词句。

## 四、边缘样式

可以做，而且不依赖 OCR。可以先提供三种：

| 样式 | 效果 | 实现难度 |
| --- | --- | --- |
| 直切 | 干净的矩形纸条 | 低 |
| 不规则剪边 | 略有倾斜、起伏的手工剪纸感 | 中低 |
| 撕纸边 | 有细碎缺口、毛边的纸片感 | 中 |

技术上是在裁出的图片上套用轮廓遮罩，外围透明，内部保留原图。还可以调整文字周围的留白。

需要把边缘效果限制在文字外侧，避免“撕掉”笔画。建议保留原始裁切区域，让用户之后能更换样式。

## 五、真正需要处理的难点

- **书页弯曲、拍摄倾斜、阴影和模糊。** 会影响识别与边界定位；第一版保留手动微调作为补救。
- **试卷的多栏、表格和公式。** 阅读顺序可能不准确，宜按区域分组展示，公式和复杂图形先支持手动框选。
- **跨行或不连续选字。** 建议生成多张纸片；如果直接裁一个大矩形，会带入不需要的内容。
- **手机上的精细操作。** 要解决选字与页面滚动冲突，并提供足够大的预览。
- **素材长期保存。** 素材库需要保存图片文件及来源、裁切位置、边缘设置，不能只记临时图片路径。

如果采用云端 OCR，会有联网等待和调用费用。可以一张图识别一次、缓存结果，之后选字和调整边缘都复用结果。

## 六、对当前项目的判断

已查看现有代码：[拼贴创作页](../pages-collage/collage-compose/collage-compose.vue)目前是“词池拖拽组成文本”，另有[拼贴图片上传页面](../pages-collage/collage-upload/collage-upload.vue)。

所以，现有入口和部分上传能力可以复用，但**图片素材库、裁切编辑器、OCR 选字界面需要新增**。

如果还要把纸片自由拖动、旋转、缩放并导出作品，则需要再做一个图片拼贴画布，这部分也应计入工作量。

## 七、建议的实施顺序

1. **先验证关键技术：** 用有代表性的书页、试卷测试“选几个字 → 裁出对应原图”，确认定位精度。
2. **做完整基础流程：** 手动裁切、个人素材库、简单拼贴画布、图片导出。
3. **接入 OCR 和边缘样式：** 先支持清晰横排印刷文字，再扩展复杂版式。

这个方向值得做。第一版范围控制好，就能实现设想中的核心体验；最先要验证的是“选字裁切是否准、是否顺手”。

本文件为可行性评估，尚未进行 OCR 样本实测或功能实现。

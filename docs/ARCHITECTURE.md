# 项目架构文档（维护版）

## 1. 文档目标与适用范围

本文件用于指导本项目的**长期维护与无损重构**，面向以下角色：
- 新接手开发者：快速理解系统结构、调用链路、边界约束。
- 需求迭代开发者：在不破坏既有行为的前提下扩展功能。
- 重构执行者：按统一分层与码风完成可回归改造。

本文件描述的是 2026-03-08 的仓库实际结构，并与以下规范配套使用：
- `docs/general-code-style-guide.md`
- `docs/no-loss-regression-checklist.md`
- `docs/layered-examples.md`

## 2. 系统总览与运行时边界

### 2.1 技术栈
- 前端：`uni-app + Vue2 Options API`（存在少量多端兼容代码）。
- 云端：腾讯云 CloudBase / 微信云开发（云函数 + 云数据库 + 云存储）。
- 核心通信：前端通过统一调用层访问云函数，云函数访问数据库集合。

### 2.2 运行时边界
- 前端负责：页面状态、交互、展示、缓存消费、错误提示。
- API 层负责：云函数参数组装、协议解包、错误归一。
- 云函数负责：鉴权、业务规则、数据读写、返回协议。

### 2.3 不可变约束（无损重构底线）
- 云函数对外协议保持兼容：函数名/action/入参/返回字段不改。
- 页面行为保持一致：loading/toast/分页/下拉刷新/回滚语义不改。
- 框架形态保持一致：维持 Vue2 Options API，不做框架迁移。

## 3. 前端分层架构

### 3.1 目录职责
- `pages/**`、`pages-user/**`、`pages-admin/**`、`pages-tools/**`、`pages-content/**`
  - 页面编排层：状态组织、生命周期、UI 事件分发。
- `api-cache/**`
  - 语义 API 层：统一解包、统一抛错、按域提供方法。
- `components/**`
  - 可复用 UI 组件与局部交互组件。
- `utils/**`
  - 无业务状态或弱状态的通用工具（时间、上传兼容、缓存键、事件总线等）。
- `cache/**` 与 `@/_utils/*cache*`
  - 本地缓存实现与命名空间管理。

### 3.2 依赖方向（强约束）
- 页面 -> API / 组件 / utils（允许）
- API -> 云调用封装 / 缓存层 / utils（允许）
- API -> 页面（禁止）
- 组件 -> 页面实例（禁止，使用 props / event）

### 3.3 页面层设计约定
- 页面不解析 `res.result.success`。
- 页面不直接拼装 action 协议（如 `action: 'xxx'`）与云函数细节。
- 页面只处理：
  - 加载态、空态、错误提示
  - 数据渲染与合并
  - 用户交互触发

### 3.4 API 层设计约定
- 每个 API 方法对外返回“业务对象”或直接抛 `Error`。
- 统一通过 `api-cache/_shared/cloud-wrapper.js` 处理：
  - `callCloudAndUnwrap`
  - `callActionAndUnwrap`
  - `isSuccessResult`
- 允许保留缓存策略差异（TTL/SWR/直连），但要在方法注释说明原因。

## 4. 云函数分层与兼容策略

### 4.1 云函数目录形态
- `functions/<functionName>/index.js`：入口层（参数校验、鉴权、分发）。
- `functions/<functionName>/handlers/**`：业务处理。
- `functions/_lib/**`：跨函数复用能力（鉴权、上下文、数据归一化）。

### 4.2 入口层职责
- 读取上下文与调用身份。
- 参数校验与默认值处理。
- 分发到具体 handler。
- 统一格式返回 `{ success, ... }` 或兼容历史 `{ code: 0, ... }`。

### 4.3 协议兼容规则
- 允许内部重排，但对外字段语义不变。
- 旧页面仍可能依赖历史字段时，优先在 API 层做兼容映射。
- 对外新增字段仅可“追加”，不可“替换/重命名”既有字段。

## 5. 核心业务时序

### 5.1 登录与身份初始化
1. 应用启动初始化云环境。
2. 恢复本地 `openid/userInfo`。
3. 必要时走匿名或显式登录流程。
4. 全局写入后页面开始拉取业务数据。

### 5.2 发布链路（add -> preview -> publish）
1. `add` 负责编辑、图片处理、草稿保存、跳转预览。
2. `preview` 负责最终参数合并、查重、上传、提交。
3. API 层执行：查重 -> 上传 -> `contentCheck`/更新接口。
4. 成功后设置刷新标记并广播事件，列表页按标记刷新。

### 5.3 详情互动链路（post-detail）
1. 拉取帖子详情与评论。
2. 点赞/收藏/关注使用语义 API，失败可回滚。
3. 评论提交完成后同步评论数到上游页面。

### 5.4 个人中心链路（profile）
1. 拉取个人资料、帖子、收藏、作品集。
2. 管理动作（删帖、取消收藏、可见性切换）走 API 语义方法。
3. 关键操作后失效缓存并派发全局事件。

## 6. 缓存模型与刷新标记

### 6.1 缓存分层
- API 缓存（命名空间 + TTL/SWR）：用于列表/详情/关系数据。
- URL 缓存（文件 fileID -> 临时 URL）：减轻重复换链开销。
- 页面局部状态缓存：用于短期 UI 恢复。

### 6.2 刷新标记语义
常见标记（示例）：
- `shouldRefreshIndex`
- `shouldRefreshProfile`
- `shouldRefreshPoem`
- `shouldRefreshMountain`
- 活动相关标记（活动列表/详情）

规则：
- 写入标记：发生“可能影响上游页面展示”的成功操作后。
- 消费标记：页面 `onShow` 或回流时消费，消费后清理。
- 不允许页面私有自定义同义标记，避免语义分裂。

## 7. 错误处理与日志规范

### 7.1 错误分层
- API 层：抛业务可读错误（`Error(message)`）。
- 页面层：统一 toast/modal 呈现，确保 loading 关闭。
- 云函数层：日志保留上下文（函数名、action、核心参数摘要）。

### 7.2 日志规范
- 统一前缀：`[module] action ...`。
- 禁止无意义刷屏日志。
- 生产敏感信息不得明文输出（token、隐私字段、完整鉴权信息）。

## 8. 质量门禁与回归映射

### 8.1 自动检查
- `npm run check:encoding`：编码/BOM/乱码特征检查。
- `npm run check:syntax`：JS 与 Vue `<script>` 语法检查。
- `npm run check:quality`：聚合质量检查。

### 8.2 手工回归（关键路径）
- 登录/注册
- 发布（含编辑、草稿、图片上传）
- 详情互动（点赞、评论、关注、收藏）
- 个人中心与他人主页
- 搜索/消息/反馈/管理员核心页

回归清单以 `docs/no-loss-regression-checklist.md` 为准。

## 9. 扩展与二开指引

### 9.1 新增页面
- 先定义页面状态与交互，再补 API。
- 不直接接入云函数协议；必须通过 `api-cache`。
- 超过阈值（行数/方法数）及时拆分到 `useXxx` 或 service。

### 9.2 新增 API 模块
- 先抽象语义方法名：`list/get/create/update/delete/toggle + Domain`。
- 统一接入 `cloud-wrapper`，返回业务对象。
- 需要缓存时明确 TTL/SWR 与失效点。

### 9.3 新增云函数 action
- 在函数入口登记 action 与参数校验。
- 返回字段与错误码需可读且可回归。
- 若前端已有同域 API，优先增量扩展而非另起重复函数。

## 10. 当前维护建议（按优先级）

1. 持续清理页面层残留的 `cloudCall + res.result`（聚焦大页面）。
2. 继续将重复逻辑沉淀到 `api-cache` 与复用组件。
3. 保持中文文案与注释 UTF-8 可读，提交前强制跑编码检查。
4. 每次重构都要附带无损回归记录，避免“结构变好但行为退化”。

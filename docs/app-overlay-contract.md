# 共用确认框与操作菜单

确认框使用居中容器，无需键盘输入的自有底部弹窗统一使用帖子操作面板的容器。登录、注册、手机验证码、自定义标签和新建收藏夹/作品集等输入表单保留原有形式；分享图片预览、全屏高光编辑和平台原生选择器保持各自用途。

## 组件与外观

- `components/overlay/AppDialog.vue`：居中确认框，无描边、32rpx 圆角、轻阴影，使用遮罩和明暗背景区分页面与弹窗。按钮沿用登录页绑定手机号底部弹窗：44rpx 胶囊圆角、至少 88rpx 高，取消为 `#f5f6f7` 底／`#666` 字，确认为 `#333` 底／白字，间距 24rpx；长按钮文案可换行增高。深色模式使用炭灰面板与浅色确认按钮。最多支持取消、额外操作、确认三个按钮；危险操作的确认按钮在浅色和深色模式下均使用 `#cc9090` 浅红色底／白字。长说明在内部滚动。
- `components/overlay/AppActionSheet.vue`：底部操作菜单默认使用 `plain`，无标题栏和顶部关闭按钮；共用整行选项、独立取消区、安全区域与进出动画。`title` 用作无障碍标签。
- 两个组件使用系统界面字体，深色模式切换为深底浅字。遮罩统一为 40% 黑色。
- `ActionMenu` 和 `DeleteModal` 都使用 `AppActionSheet` 的 `plain` 样式：无标题栏和顶部关闭按钮、整行居中、可选辅助说明、独立取消区，浅色为白底深字，深色为炭灰底浅字，底部留出安全区域。外层帖子菜单的编辑、组诗合成、隐藏和删除入口使用普通文字色；“取消隐藏”和删除面板的“删除帖子”使用适配浅色/深色模式的红字，后者另有永久删除说明。
- 取消操作文案共用全局主题 mixin 的 `cancelActionStyle`：取消收藏、取消关注、取消隐藏、取消下载，以及底部菜单/底部表单的“取消”使用浅色 `#c43d3d`、深色 `#f08a8a` 警示文字，背景和行为保持不变。居中弹窗里单纯的“取消”保留原来的灰色；“取消关注”等具体操作即便作为居中确认按钮仍标红，并按实色背景使用有对比度的红色。“完成”“跳过”“稍后再说”和说明正文不变色。
- `plain` 菜单以 240ms 从底部滑入、180ms 滑出，遮罩同步淡入淡出；关闭动画完成后再发出操作或取消事件，下一级面板随后展开。关闭期间拦截重复点击和物理返回，外部关闭、重开或卸载会撤销待执行事件。`uni.showActionSheet`、头像和背景操作同样在退出动画后回调。系统减少动态效果设置下缩短视觉动画。
- 发布模式使用整行操作；配色、字体、收藏夹、作品集、默认头像和云提示使用默认插槽保留必要的选择内容。插槽提供 `select(value)`，也可通过组件引用调用 `selectValue(value)`，用于退出动画完成后提交选择。字体实时预览保持原逻辑，底部显示“完成”；提示底部显示“知道了”。其余面板显示“取消”。
- 收藏夹/作品集的“创建”在列表退出后打开居中输入表单；两个列表页和两个选择器共用 `styles/collection-create-dialog.css`，面板、遮罩、胶囊按钮和明暗配色与 `AppDialog` 一致，无黑色描边。创建面板使用独立类名，避免旧弹窗样式覆盖；内容区可滚动，底部操作保持可见。取消创建后回到选择列表，接口失败时列表继续显示以便重试。关闭列表直接更新 Vue 状态并触发 `hide`，避免旧 `setData` 对 `propsData` 的读取中断关闭回调。
- “修改收藏夹名字”和“修改作品集名字”表单复用同一居中样式，保留名称预填、封面选择/替换和保存逻辑。收藏夹列表页的新建表单支持可选封面，通过 `readFileAsBase64` 读取各端临时图片，上传成功后将文件 ID 传给 `createFavoriteFolder`；上传或创建失败保留名称和选图，处理中阻止重复提交，取消/成功后清空表单。
- 作品集详情的“批量添加作品”复用同一居中面板和按钮，取消文字保持灰色，面板与列表项无描边；说明及作品列表共用一个内容滚动区，标题与底部操作固定。保留作品多选、选中勾号、添加数量和未选择时禁用添加的行为。
- 帖子删除面板提供“删除并存为草稿”“仅自己可见”“删除帖子”。存草稿仍在保存成功后删除原帖；“仅自己可见”复用隐藏功能，已隐藏时禁用该项，不会再次切换成公开。原有 `close`、`save-draft`、`confirm` 事件保留，新增 `hide` 事件。
- 头像、收藏夹删除和微信绑定确认继续使用共用确认框。个人页“移除背景”确认复用背景设置的 `AppActionSheet`，显示红色“移除背景”、确认说明及独立取消区；选中后等待面板退出动画完成再移除，取消、遮罩和返回键只关闭面板。
- 退出登录确认复用 `AppActionSheet` 的 `plain` 样式，显示红色“退出登录”、确认说明和独立取消区；关闭动画完成后执行退出，取消、遮罩和返回键仅关闭面板。
- 个人页收藏列表与收藏夹内容页统一使用右上角三点入口，打开 `FavoriteActionMenu` 的底部菜单：“放入收藏夹”“取消收藏”及独立取消区。取消收藏在菜单退出后按 `favoriteId` 移除当前收藏记录，成功后更新列表；失败保留原项。“放入收藏夹”在退出后按帖子 ID 打开已有收藏夹选择器，保留原收藏并添加到所选收藏夹，不移动或删除原帖。两页显式引入组件，避免正式包依赖自动扫描。
- 需要等待接口的受控确认框传入 `busy`；处理中禁用按钮，处理结束后允许重试，避免连续点击重复提交。

## 短过渡（2026-09-29）

- 居中确认框、收藏夹/作品集创建与编辑、批量添加、标签选择和账号/手机号输入表单共用 `styles/overlay-motion.css`：进入 180ms、退出 120ms，无额外停顿。居中面板轻微缩放，底部输入表单仅作短距离位移，遮罩同步淡入淡出。原有 `AppActionSheet` 的 240/180ms 全距离滑动保持不变。
- 输入表单使用 `components/overlay/AppMotion.vue` 保留关闭期间的节点。取消和返回通过 `dismiss()`，在退出后清空输入、返回列表或跳转；`dismiss(callback)` 可在退出后执行注册“跳过”等下一步。直接受控关闭也保留退出过程；重开、外部关闭及卸载取消旧的待执行回调。微信端启用 `virtualHost`，通过显式 `maskClass` / `maskDark` 将原遮罩样式传到真实根节点，不依赖全局属性合并选项；默认插槽不增加布局层。
- API 宿主为 `AppDialog` 开启 `deferAnswer`，在退出完成后回调并展示下一个请求。直接使用的受控确认框仍立即提交业务事件，以支持接口处理中的 `busy` 和失败重试；业务关闭 `visible` 后执行退出动画。退出期间拦截重复点击和返回，导航回调前释放返回拦截。
- 列表点赞图标与数字、详情点赞图标随同一帖子的状态变化触发 200/160ms 轻反馈；首次加载和列表复用到另一篇帖子时不触发。详情标签绑定到实际的 `.post-tags`，180ms 淡入，不加延迟。以上新增效果支持系统减少动态效果设置。
- 新增 `scripts/test-dialog-motion.cjs`（纳入 `test:overlays`），覆盖退出时机、重复点击/返回、忙碌与重试、输入保留、跳过回调、外部关闭、快速重开和卸载清理。`scripts/test-dialog-motion-h5.cjs` 验证实际 CSS 时长、明暗主题、遮罩关闭、点赞再次触发/列表复用及减少动态效果。真机键盘、返回键和小程序观感仍需设备验收。

## 页面接入

### 侧栏与筛选过渡（2026-09-29）

- 个人页侧栏复用 `AppMotion` 的 `drawer` 模式：180ms 滑入、120ms 滑出，遮罩同步淡入淡出，以 `transform` 替代 `left` 动画。遮罩、物理返回和菜单共用退出过程；导航与退出登录面板在退场完成后执行，移除原来的独立 100ms 定时器。父页关闭使用显式 `false`，避免重复回调反向打开侧栏。
- 首页和诗歌广场筛选使用 `popover` 模式：150ms 短距离淡入、120ms 退出，保留透明点击遮罩与原面板外观。选择后等退场结束再更新列表，诗歌广场进入关注模式不会提前卸载退场节点。首页只在接受点击时检查滚动防误触，已接受的选择不会因退出期间防误触状态变化而丢失。
- 三个页面隐藏时撤销待执行动作，避免切换页面后才跳转或刷新旧列表。所有新效果遵循减少动态效果设置；原字体路径、页面注册时机及绘制名称未改动。
- `node scripts/test-navigation-motion-h5.cjs` 使用真实组件与页面方法、替代数据加载和导航，验证两种主题下的时长/位置、遮罩和返回、关闭后执行、重复操作、页面隐藏撤销和减少动态效果。截图保存在系统临时目录的 `enterkey-overlay-review`；App/微信真机观感仍需验收。

每个自有路由页面的模板末尾放置一个 `<app-overlay-host />`，由 `main.js` 显式导入并通过 `app.component('app-overlay-host', AppOverlayHost)` 注册，不得仅依赖 easycom 自动扫描。新增页面时也必须添加；`scripts/test-app-overlays.cjs` 检查 pages.json 中的页面是否接入，并验证宿主注册和真实组件的请求回调。

2026-09-29 排查本地 Android 正式包 `unpackage/release/apk/app-release.apk`：包内 `app-service.js` 与 2026-09-28 的发行产物一致，69 处页面保留了 `resolveComponent("app-overlay-host")`，但没有宿主实现或全局注册；调试产物则包含 easycom 引入及宿主实现。由此造成 API 请求进入队列后无人展示，确认流程无法继续；直接引用 `AppActionSheet` 的菜单仍可显示。显式注册保证宿主进入依赖图。尚未据此确定 HBuilderX 自动扫描失效的具体编译器原因；修复后仍需重新发行 APK 真机验收。

`main.js` 安装 `utils/appOverlay.js` 的适配器与页面生命周期 mixin。现有业务继续调用 `uni.showModal` / `uni.showActionSheet`，不需要重写确认和取消分支。系统权限授权、图片选择等平台功能不拦截。尚无页面的启动阶段和第三方升级页面保留平台弹窗兜底。

适配器支持现有的标题、正文、按钮文字、单按钮提示、输入框和操作列表；普通按钮颜色统一，危险按钮按操作文案标记，不沿用各页面分散的 confirmColor 配色。

网页链接页 `pages-tools/web-link/web-link` 保留挂载点，但 API 确认框和操作菜单使用平台原生实现，避免请求排队后无人展示，以及自绘弹层被原生 `web-view` 遮挡。参见 [web-view 层级说明](https://uniapp.dcloud.net.cn/component/web-view#web-view组件的层级问题解决)。

App 的未登录提示通过 `authHelper.requireLogin()` 调用 `appOverlay.showNativeModal()`，直接使用适配器安装前保留的系统弹窗，避免正式包中自绘登录提示不显示时阻断入口。底栏“我”与发布页“写诗”共用此路径；确认进入登录页，取消保留各入口原有行为。H5 和小程序的提示方式保持原有逻辑。此项为临时兜底；宿主显式注册修复通过正式包真机验收前继续保留。

## 交互约定

- 同一页面的 API 请求按顺序展示，不能覆盖尚未回答的确认框。
- 确认框默认不允许点击遮罩关闭；已有自绘确认框可用 `closeOnMask` 保留原有行为。底部菜单允许点遮罩、关闭和取消。
- `showCancel: false` 的提示不会被返回键当作确认，也不会通过返回键跳过。
- 有弹层时 App 返回键先处理最上层；发布页的草稿返回拦截优先尊重弹层处理结果。
- `event.from === 'navigateBack'` 的主动导航不由全局弹层拦截；发布页已完成草稿选择后也应先放行主动返回，避免弹窗尚未卸载时吞掉跳转。物理返回仍优先处理弹层。
- 点击结果只提交一次。接口回调保留 `success`、`fail`、`complete`，无回调时返回 Promise；菜单取消走 fail/reject，确认框取消走 success/resolve 的 `cancel: true`。
- 页面隐藏或卸载时，尚未回答的 API 请求以 `fail page closed` 结束，防止确认结果误用到另一个页面。
- 新增有自身 `onBackPress` 的页面时，参照发布页处理 `event.appOverlayHandled`，避免页面退出逻辑覆盖弹窗的返回处理。

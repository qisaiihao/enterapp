适用于所有页面的通用重构SOP (Standard Operating Procedure)
核心哲学：先解耦，后拆分。每一步都进行验证。
对于您项目中的任何一个 .vue 页面，请严格遵循以下步骤：
阶段一：分析与准备 (耗时10%)
在动手修改任何代码之前，先做好侦察工作。
选择目标页面: 选择您下一个要重构的页面（例如 post-detail.vue）。
分析 <script>:
识别API调用: 找出所有 this.$tcb.callFunction(...) 的地方。问自己：“这是在操作哪个资源（帖子、评论、用户）？”
识别工具函数: 找出所有可以脱离组件存在的纯函数（如数据格式化、URL处理、复杂计算等）。
识别页面逻辑: 剩下的就是只与本页面强相关的逻辑（如弹窗的显示/隐藏、动画控制等）。
分析 <template>:
寻找“块”: 找出页面上独立的、有明确边界的UI区域。例如：帖子头部、作者信息卡片、评论区、评论项、相关推荐列表等。这些都是组件的候选者。
寻找“循环”: 任何 v-for 循环内部的内容，几乎都是一个完美的组件拆分对象（例如评论列表中的每一个评论项）。
阶段二：执行重构 (耗时80%)
这是流水线的核心工序，严格分为“逻辑”和“视图”两步。
A. 逻辑层解耦
迁移API调用:
打开 src/api-cache/ 目录。
根据您在步骤3中识别的资源，找到对应的文件（如 post.js, comment.js），如果没有就创建一个。
将被识别出的API调用封装成独立的、语义化的函数（如 getPostDetail(postId), postComment(data)），并 export。
关键: 在函数内部，使用您项目已有的 utils/cloudCall.js。
迁移工具函数:
打开 src/utils/ 目录。
将被识别出的工具函数，放入对应的文件中（如 time.js, formatters.js），并 export。
替换并验证:
回到目标页面，在 <script> 顶部 import 您刚刚创建的API函数和工具函数。
用新函数替换掉页面中原有的内联逻辑。

B. 视图层拆分
创建子组件:
根据您在步骤4中识别出的UI“块”和“循环项”，在 src/components/ 目录下创建新的 .vue 组件（例如 CommentItem.vue, AuthorCard.vue）。
定义“组件合同” (Props & Events):
Props (数据向下流动): 在新组件中，明确定义它需要从父组件接收哪些数据。
在父组件中实现:
在目标页面（父组件）的 <template> 中，删除旧的大块HTML，替换为新的组件标签 (<CommentItem :comment="item" @reply="handleReply" />)。
在 <script> 中 import 并注册新组件，并实现监听事件的方法 (handleReply)。
迭代与验证:
重复步骤8-10，直到您觉得页面 <template> 已经足够清晰为止。
阶段三：收尾与合并 (耗时10%)
最终测试: 对整个页面进行一次完整的功能回归测试，确保所有功能（包括各种边缘情况）都正常。
代码清理: 删除被注释掉的旧代码，检查新代码的格式和命名规范。
